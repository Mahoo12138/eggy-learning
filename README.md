# Embedded · 学习工作台

深圳招聘技能调研、三项目课程，以及按真实可用时间推进的个人学习管理。服务端和测试使用 Node 内置模块，没有 npm 依赖，不需要构建或 `npm install`。

## 启动

需要 Node.js 22 或更新的 LTS 版本。Git 历史视图另需本机 Git；没有 Git 时课程与记录仍可保存。

```sh
cp .env.example .env.local
node server.mjs
```

已有 `.env.local` 时直接运行第二条命令。当前工作区已配置学习者邮箱；新克隆复制示例即可。服务自动读取 `.env.local`，终端环境变量优先；配置变化需重启。

- 首页：<http://127.0.0.1:3000/>
- 学习者工作台：<http://127.0.0.1:3000/learner.html>
- 管理者工作台：<http://127.0.0.1:3000/admin.html>
- 当前课程路线：<http://127.0.0.1:3000/plan.html>
- 2026-10-12 招聘调研快照：<http://127.0.0.1:3000/report.html>

默认仅本机访问。可信局域网使用：

```sh
node server.mjs --host 0.0.0.0 --port 3000
```

用本机局域网 IP 访问。两个工作台都无密码，按操作分工组织页面，共用一份数据。页面分工不是身份认证，能访问服务的人仍可切换入口。若使用自定义局域网域名，在 `.env.local` 配置 `ALLOWED_HOSTS=study.local`；域名仍须指向本机。该配置不提供公网认证。

## 两个人如何使用

| 使用者 | 页面职责 |
|---|---|
| 学习者 | 查看自己的状态，完成训练与题目作答，保存草稿、证据、验收复盘；按实际容量调整本周计划与延期 |
| 管理者 | 查看整体状态与学习档案，维护阶段、单元、任务、题目和计划；训练档案只读，不在管理页代填作答或验收 |

学习者页不包含课程编辑表单，管理者页不包含训练填写表单。二者读取同一份课程和学习档案，共同维护周安排；版本检查继续防止两个人同时保存时互相覆盖。管理者更新题目后，学习者点击“更新任务要求”即可看到新版本，原作答快照仍保留。归档题目的未保存答案留在“旧题草稿”，可导出后处理。Git 提交仍按实际 Author 邮箱分类，不取决于使用哪个页面。

## 数据与 Git

| 文件 | 内容 |
|---|---|
| `data/curriculum.json` | 阶段、单元、任务、题目、验收标准 |
| `data/units/<id>.json` | 实际训练、草稿、答案、证据、复盘与检查项；首次保存才创建 |
| `data/schedule.json` | 周容量、原安排、调整版本、核对与延期去向 |
| `public/report.html`、`public/docs/`、`public/research/` | 保留采集口径的招聘调研快照与证据 |
| `docs/当前学习训练计划.md` | 从当前课程按需导出的 Markdown |

保存成功代表文件写入工作区，**不代表已经提交或推送**。在终端按需要提交与同步；页面不自动运行 commit、pull、push，也不替你修改 Git 身份。停止服务后再 pull、切分支或恢复文件；解决冲突后重新启动。主题和页签偏好只保存在浏览器。

```sh
LEARNER_GIT_EMAIL=mahoo-pig@qq.com
```

以上环境变量按 Git **原始 Author 邮箱**分类：匹配为学习记录，其他为维护记录。Committer、提交标题、文件路径和 `.mailmap` 不改变分类。未提交的内容不猜测作者。视图只覆盖当前仓库 HEAD 可达的本地历史，合并提交有标签，浅克隆有提示；不会同时扫描三个项目各自的代码仓库。

Git 学习记录是提交分类，不等于一次训练、出勤或验收。管理者维护课程、计划、题目；学习者保存实际训练和作答。此分工不是权限控制。`.env.local`、运行锁和临时文件已忽略；`.env.example` 与 `data/` 应跟随仓库保存。

## 使用顺序

1. 管理者在管理者工作台的“课程与题目”调整现有阶段、任务与题目。已有历史的内容用归档；实质验收要求变动会进入待复核。
2. 学习者在学习者工作台的“训练与记录”选择单元和任务，保存草稿或正式训练。失败记录保留；同一任务复测通过才能关闭卡点。通过独立验收并完成标准检查后才计为单元已验收。
3. 学习者在“我的周计划”、管理者在“周计划维护”填写实际可用时段，选择这次真正要做的目标与预计分钟，预览后应用。时段、缓冲和任务不能超过容量。
4. 周末核对原安排，记录实际情况。未完成内容先续做，有余量再学新内容；考试周允许暂停。恢复时把短检查算进可用时间。延期不会清零已学内容，也不会累积补课欠账。
5. 管理者查看学习档案中的成果、答案和卡点，再按需要调整课程。双方在各自页面查看 Git 提交与导出数据；学习者查看学习提交，管理者查看维护提交。课程 Markdown 可用下面的命令重新生成。

```sh
node scripts/export-plan.mjs
node --test
```

题目区包含任务提问与练习思考题，支持提示与折叠参考要点。正式作答保存原题版本和快照；修改题目不覆盖旧答案。更正误记会保留原记录并只计算有效版本；真正的复测另记一次真实用时。

## 保存与恢复

不同标签页使用版本检查；旧页面保存会报冲突，输入保留，可下载未保存内容后读取远端比较。网络失败显示未保存，不切回浏览器里的另一套正式数据库。请求重复发送不会重复记账。

服务使用单进程写队列和同目录临时文件替换。一个数据目录只允许运行一个服务；启动时校验 JSON、课程引用和历史。文件损坏或 Git 冲突会指出文件，不会用空数据覆盖。异常终止后会检查旧锁的进程是否仍存在；锁文件本身损坏时，在确认无服务运行后检查 `.local/server.lock`（及 `.reclaim`），再恢复启动。

Git 只保护已提交的数据；未提交学习记录仍需要备份。网页可导出 JSON，用于留存和核对；首版不提供整库导入覆盖按钮。需要恢复时停止服务，从可信 Git 版本恢复相应数据文件，再运行测试并启动校验。

原浏览器 localStorage 不再作为数据源，也不会被自动清空。初始课程已迁入 `data/`，旧学习页、浏览器存储逻辑及学习页 Python 生成器已移除。招聘调研和证据保留为历史快照，当前课程以 `/plan.html` 和管理者工作台为准。

根目录的 `render_learning_report.py`、`learning_report_template.html`、`visuals.html` 仅保留为历史研究快照的生成源码，不是当前入口，也不是 Node 服务依赖；不要用它们覆盖现有页面。研究报告统一从 `/report.html` 进入，原始采集 Markdown、JSON 和证据继续保留。

架构与规则见 [Node 零依赖改造方案](Node零依赖改造方案.md)，代表性测试和浏览器核验范围见 [实施验证](docs/实施验证.md)。
