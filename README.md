# 蛋仔编程乐园

一个供一位学习者和一位管理者在本机使用的编程课程工作台。课程先用两个段位系统训练 C 编程、数据结构、指针、内存与文件，再进入 Linux 使用基础，并沿九个段位继续学习 STM32、Linux 系统编程、C++ 并发、网络、SQL 与 SQLite，最后完成一件可独立说明和交付的作品。

当前版本已经替代旧的“三项目学习工作台”。学习过程围绕短关卡和即时反馈展开：练习获得经验，首次独立完成变式获得星星，综合挑战通过后晋段；经验、星星和段位不会因失败而扣除。前三个段位在网页内完成互动训练，后六个段位各完成一件主题作品。

## 启动

需要 Node.js 22 或更新版本。服务端与基础自动化测试不需要 npm 依赖；前端高亮库随项目同源提供，不需要执行 `npm install`。前端使用原生 Web Components 与浏览器 ES Modules，没有打包步骤；可选浏览器 QA 使用独立环境中已有的 Playwright。

```sh
cp .env.example .env.local
node server.mjs
```

已有 `.env.local` 时直接启动服务。默认地址为：

- 首页：<http://127.0.0.1:3000/>
- 蛋仔岛大厅：<http://127.0.0.1:3000/learner.html>
- 首个游玩关卡：<http://127.0.0.1:3000/play.html?level=quail-fountain-sequence>（也可从大厅进入当前关卡）
- 九阶段位地图：<http://127.0.0.1:3000/plan.html>
- 岛务管理处：<http://127.0.0.1:3000/admin.html>
- 2026-10-12 招聘调研历史快照：<http://127.0.0.1:3000/report.html>

可以指定端口：

```sh
node server.mjs --port 3100
```

需要在可信局域网内访问时：

```sh
node server.mjs --host 0.0.0.0 --port 3000
```

此模式没有账号、密码或角色隔离。任何能访问该地址的人都能打开学习者页、管理页并修改同一份数据，因此只适合本机或可信局域网。自定义局域网域名可在 `.env.local` 中加入 `ALLOWED_HOSTS=study.local`；这只是 Host 白名单，不是身份认证。

鹌鹑蛋和鸽子蛋的 C 代码会在服务端真实编译和运行。当前 C 运行器面向 macOS，使用 `/usr/bin/clang` 与 `/usr/bin/sandbox-exec`；缺少任一工具时，页面会明确返回运行器不可用。在线 C 关卡只开放课程需要的标准头文件和临时工作目录，并限制源码、输入、输出、文件大小与运行时长。鸡蛋段位使用确定性的虚拟 Linux 终端，练习目录、权限、管道和进程命令，不执行宿主机 Shell，也不读取宿主机文件。后续 Linux 系统编程、STM32 与综合作品按课程提示使用本地工具链或真实硬件。

## 从哪里开始

学习者打开“蛋仔岛大厅”，进入当前技术关卡。前两段直接面对 C 代码、输入、内存和文件，第三段直接面对 Linux 系统概念、目录和终端命令；这些题目不展示建筑或道具场景。每次只显示一个步骤：观察示例、预测、运行观察、解释、引导修改、即时反馈和独立变式。鹅蛋及后续段位再以乐园建筑和道具为作品灵感，把一段技术整合成可运行、可解释的成果。需要外部 AI 帮助时，可一键复制当前关卡、代码或命令、错误和已尝试方法；外部聊天正文不会回写课程记录。

管理者在“岛务管理处”查看当前段位、经验、星星、答题与代码、提示使用情况、作品进度、荣誉墙和本周游玩卡，也可以维护课程内容。学习者和管理者读写同一组 JSON 文件；页面名称只表示操作分工。

课程工坊的“模拟学习”在弹窗中展示当前草稿的学习者视角，不必先保存。可以直接切换题目、章节和 Boss，查看提示并运行代码；模拟尝试不写入学习档案，也不影响经验、星星和真实学习进度。关闭或重置后清空本次模拟。

在线章节的练习完成与独立星星分开记录：代码通过评分即可完成本章并继续下一章；看过完整答案的变式不授独立星星。段位地图逐章显示完成与授星状态，点“补星挑战”直接进入独立练习。鹌鹑蛋三章在原变式答案耗尽后自动提供新的参数化等价题；查看补星题答案后仍可获得下一题，独立通过才授星。其他章节使用原有等价题库。Boss 仍须补齐规定星数才能进入。

补星题由服务端确定性生成，初始接口不下发完整解法；历史答案曝光、经验、课程版本和既有奖励保持原记录。回访较早章节获得最后一颗所需星星时，当前学习位置会推进到 Boss。

本周游玩卡只安排一个主要目标，并可附加一个短关卡。休息周不会生成欠课、补做或惩罚。没有完成的内容保留原进度，下次继续。

## 九阶段位课程

九阶指九个全局段位。段位地图展示学习路线，每个段位绑定对应的技术训练或作品。

| 段位 | 技术主线 | 主要成果 |
|---|---|---|
| 鹌鹑蛋 | C 编程基础、可靠输入、流程控制与函数调用 | 3 个互动关卡 + C 综合 Boss |
| 鸽子蛋 | C 数组、结构体、指针、动态内存与文件 | 3 个互动关卡 + 数据与资源 Boss |
| 鸡蛋 | Linux 系统、目录路径、权限、管道与进程基础 | 3 个互动关卡 + 终端排障 Boss |
| 鹅蛋 | C 数组、字符串、结构体、指针、内存、文件与系统化调试（项目整合） | 蛋仔食堂·今天吃什么 |
| 鸵鸟蛋 | STM32 启动链、GPIO、非阻塞时间、PWM、中断、UART、ADC、I²C、看门狗与安全状态机 | 蛋仔摩天轮安全中控站 |
| 恐龙蛋 | Linux C、系统调用、虚拟内存、多进程、IPC、事件循环、资源隔离与恢复 | 蛋仔岛夜班巡检台 |
| 巅峰凤凰蛋 | C++ 封装与 RAII、密集计算、数据局部性、线程池、库存一致性与安全停机 | 蛋仔商城道具配送中心 |
| 超级凤凰蛋 | TCP 消息边界、超时重试、有界并发、SQLite 事务、持久化去重与重启恢复 | 蛋仔游戏厅联机积分中心 |
| 无敌凤凰蛋 | 独立架构、跨领域整合、故障恢复与可接手性 | 自主作品，参考题为蛋仔岛开园运营系统 |

完整关卡和章节见网页中的段位地图或生成的 [docs/当前学习训练计划.md](docs/当前学习训练计划.md)。三个完整作品课程的设计说明见 [docs/蛋仔食堂完整课程大纲.md](docs/蛋仔食堂完整课程大纲.md)、[docs/蛋仔摩天轮安全中控站完整课程大纲.md](docs/蛋仔摩天轮安全中控站完整课程大纲.md) 和 [docs/蛋仔岛夜班巡检台完整课程大纲.md](docs/蛋仔岛夜班巡检台完整课程大纲.md)。重新生成 Markdown：

```sh
node scripts/export-plan.mjs
```

第七章“巅峰凤凰蛋”保留商城配送中心方向，提供 10 个小节、30 个可累积代码增量。课程大纲见 [docs/蛋仔商城道具配送中心完整课程大纲.md](docs/蛋仔商城道具配送中心完整课程大纲.md)，完整 C++20 工程见 [courseware/peak-delivery-center/project](courseware/peak-delivery-center/project)。每个引导步骤展示需要复制的完整文件、一个有界实验、验证命令和预期现象，章末可以核对整份快照；最后按同一组文件构建完整配送程序。网页负责概念题、源码呈现与学习记录，C++ 编译、计算计时和并发测试在本地工具链执行。

```sh
cd courseware/peak-delivery-center/project
make test
make run
make benchmark
```

代码包位于 `data/project-code/peak-delivery-center-project.json`，独立于课程正文按需加载；模拟学习也会加载与草稿引用一致的已发布代码包。维护课件源码时，停止学习服务，修改 `courseware/peak-delivery-center/generate.py` 并运行 `python3 courseware/peak-delivery-center/generate.py`，再用 `node scripts/sync-peak-code-package.mjs` 同步代码包摘要和课程镜像，最后运行 `node scripts/export-plan.mjs` 更新训练计划并重启服务。

第八章“超级凤凰蛋”保留联机积分中心方向，按 10 个小节、30 个完整代码增量构建 C 客户端、C 网关、C++ 服务与 SQLite 数据库。课程大纲见 [docs/蛋仔游戏厅联机积分中心完整课程大纲.md](docs/蛋仔游戏厅联机积分中心完整课程大纲.md)，最终工程见 [courseware/super-arcade-data-center/project](courseware/super-arcade-data-center/project)。每步都有完整文件、一个小范围实验和验证命令；章末快照与最终工程使用同一条累积代码链。网络故障和数据库测试在本地工具链执行，网页负责概念理解、源码交付与学习记录。

```sh
cd courseware/super-arcade-data-center/project
make test
make run
```

维护超级凤凰蛋课件时，先停止学习服务，运行 `python3 courseware/super-arcade-data-center/generate.py`，再运行 `node scripts/sync-super-code-package.mjs --check` 验证交付链，去掉 `--check` 后同步源码包与课程镜像。正文草稿需要一起发布时加 `--with-draft`；脚本会先校验整份课程再原子发布，并仅在内容变化时增加课程版本。最后运行 `node scripts/export-plan.mjs` 更新训练计划并重启服务。

## 前端模块

代码高亮、选择输入、本周游玩卡、声音与动效设置、通知提示已封装为 Web Components，通过页面入口的 ES Module 导入使用。组件保留原生表单与键盘行为；具体接口、业务范围和外部 ESM 规则见 [docs/前端模块与组件.md](docs/前端模块与组件.md)。

## 数据与版本

作品源码包的发布、校验、缓存与维护命令见 [docs/源码交付维护.md](docs/源码交付维护.md)。四个源码同步脚本均支持 `--check`，真正发布时与学习服务共用运行锁。

| 路径 | 内容 |
|---|---|
| `data/course.json` | 九阶段位课程索引、作品场景、可选素材、奖励和成就定义 |
| `data/levels/*.json` | 互动关卡、Boss 与六个段位作品的详细内容 |
| `data/progress.json` | 当前关卡、经验、星星、尝试记录、作品战利品和成就墙 |
| `data/week-card.json` | 本周游玩卡、休息周和幂等回执 |
| `public/docs/`、`public/research/` | 招聘调研的历史证据与结构化快照 |

写入接口使用版本检查、稳定请求编号和单进程写队列。单文件记录通过同目录临时文件替换；课程索引与多份详情先复制到完整暂存目录，校验后再以目录交换一次发布，异常时从唯一备份回滚或恢复。相同请求重试不会重复发放经验或星星；旧版本并发保存会被拒绝。服务启动时会校验课程、关卡、进度和周卡；若从唯一有效备份恢复损坏的当前数据，原现场会保留为 `.data-rejected-current-*`，不会被空文件覆盖或静默删除。

网页保存只表示工作区中的文件已经更新，不表示 Git 已提交或推送。停止服务后再执行 pull、切换分支或恢复数据；解决冲突并运行验证后再启动。`.env.local` 与 `.local/` 不进入 Git，课程和学习记录应按需要纳入版本控制与备份。

`.env.local` 中的 `LEARNER_GIT_EMAIL` 只用于管理页区分学习者与维护者的本地 Git 提交：系统按原始 Author 邮箱完整匹配，不会修改仓库或全局 Git 身份。Git 提交历史也不等同于关卡尝试、星星或作品验收。

## 验证

运行完整自动化测试（领域规则、C 运行器、虚拟 Linux 终端、Git 历史读取和 HTTP/文件接口）：

```sh
node --test
```

测试会使用临时目录，不应污染正式学习数据。具体通过数量以当前命令输出为准；浏览器闭环及仍未覆盖的硬件和作品源码范围见 [docs/实施验证.md](docs/实施验证.md)。学习产品参考与取舍见 [docs/学习机制参考与设计取舍.md](docs/学习机制参考与设计取舍.md)，架构与约束见 [Node零依赖改造方案.md](Node零依赖改造方案.md)。
