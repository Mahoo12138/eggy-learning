# 蛋仔食堂完整课程大纲

## 1. 课程定位

“蛋仔食堂”是鹅蛋段位唯一的累计作品。学习者会在同一个 Windows C17 工程中，从空目录开始，逐步完成一个不依赖第三方库的终端应用。课程的业务主轴始终是推荐：菜品、分类、标签、历史和持久化都是推荐系统的输入，最终输出是一次可解释、可接受、可重抽的推荐结果。

这不是只给需求清单的开放作业。15 章中的产品主线代码全部由课程逐步引导完成，学习者每次只接手一个已经讲过、边界清楚的独立变化。自由选择架构、功能和视觉方向的任务只保留给最后的独立项目。

课程遵守以下规则：

- 15 章共同修改一个代码库，不创建互不相干的小项目。
- 每章先完成 1 个概念理解课，再进入 3 个完整引导课和 1 个受限独立检查。
- 概念理解课从可观察现象出发，用心智模型、术语白话解释和代码映射回答“为什么这样写”，通过两道理解题后才解锁代码。
- 每个引导课从上一课的可运行快照开始，并以新的可运行快照结束。
- 每段新增代码都要配套编译命令、运行操作、预期画面和常见失败定位。
- 独立检查只迁移已学概念，不要求学习者自行发明模块或架构。
- 查看完整解法后不扣除已经获得的奖励；当前变式不授星，系统改派未见过的等价变式。
- Boss 只整合、排错和验收已经出现过的能力，不偷偷加入新知识点。

## 2. 课时与完成标准

- **章节场次：**15 章共 75 场
- **Boss 场次：**4 个阶段各 1 场，完成全部章节后单独解锁
- **项目估算：**`estimatedSessions.minimum = 75`，`estimatedSessions.typical = 79`
- **单次时长：**20–25 分钟
- **总学习时间：**约 26–33 小时，工具链安装、环境配置和环境故障排查另计
- **内容构成：**15 个概念理解课、45 个完整引导课、15 个受限独立检查，以及解锁后的 4 个 Boss 阶段

15 章均按“1 个概念理解课 + 3 个完整引导课 + 1 个受限独立检查”安排，共 75 场。概念理解课不发经验或星星；两道理解题的作答与反馈由服务端保存，管理者可以查看。学习者完成第 15 章独立检查、取得全部 15 颗章节星星后，才解锁 Boss。Boss 的四个阶段各占 1 场，支持按阶段保存和继续，不与第 15 章检查合并，因此典型总量为 79 场。

完成课程时，学习者应交付：

1. 可在 Windows 10/11 上构建运行的 C17 终端应用。
2. 菜品、分类、标签、历史、设置和推荐策略的完整实现。
3. 基础随机、范围过滤、排除最近、去重轮次和整数加权推荐。
4. 可配置的抽奖动画以及 Enter、Esc、`f` 等完整交互。
5. UTF-8 版本化数据文件和替换式崩溃保护。
6. 自动检查、故障复现记录、内存泄漏报告和发布构建说明。

## 3. 已确定的产品语义

### 3.1 推荐是主轴

推荐视图是默认主视图。管理页面只负责准备和修正推荐所需要的数据，不与推荐争夺产品中心。

推荐引擎的输入是：

- 可选分类；
- 零个或多个必备标签，多个标签采用“同时具备”的交集语义；
- 排除模式（不排除、排除最近抽到、排除最近接受）与天数 N；
- 去重轮次开关；
- 加权策略开关；
- 当前时间和可替换的随机数源。

推荐引擎的输出是菜品 ID 或明确的“没有候选”结果。引擎不绘制界面，也不直接读取按键。

### 3.2 `RECOMMENDED` 与 `ACCEPTED`

抽奖动画中快速滚动的名字只是视觉预览，不算推荐，不更新业务数据。动画最终定格时产生一次 `RECOMMENDED`：

- 更新菜品的 `lastRecommendedAt`；
- `recommendCount` 加一；
- 写入一条包含时间、菜品 ID 和筛选条件快照的历史记录。

结果定格后：

- Enter 产生 `ACCEPTED`，表示“就吃这个”，同时更新 `lastAcceptedAt` 并让 `acceptCount` 加一；
- Esc 保留刚才的 `RECOMMENDED`，并从当前条件重新抽取；
- `f` 切换收藏状态，立即尝试持久化，并影响以后启用加权策略时的权重。

课程同时提供两种含义明确的时间策略：

- “排除最近抽到”严格读取 `lastRecommendedAt`；
- “排除最近接受”严格读取 `lastAcceptedAt`。

两种策略不会共用或猜测彼此的字段。`recommendCount` 统计定格次数，`acceptCount` 统计 Enter 接受次数。

### 3.3 删除后的历史

菜品删除后，历史不能失去可读性。历史记录保存菜名和筛选条件快照：

- 对应菜品仍存在时，可以从历史回跳详情；
- 对应菜品已删除时，仍显示当时的快照，并明确标记“菜品已删除”；
- 不为了维持链接而把已删除菜品继续放进推荐候选。

## 4. 技术基线

### 4.1 运行环境

- Windows 10/11
- C17
- CMake
- 课程基准工具链为 MSVC 与 Windows SDK
- 只使用 C 标准库和 Win32 API，不使用第三方 TUI、数据库、JSON 或随机库
- 编译期打开 Unicode 定义和较严格警告；最终发布构建以 `/W4` 无新增警告为目标

### 4.2 终端输出链路

最终渲染链路固定为：

```text
Frame 逻辑字符帧
    ↓
VT 编码器（光标、颜色、字符、换行）
    ↓
单次或少量批次 WriteConsoleW
    ↓
Windows 控制台备用屏幕
```

`Frame` 是二维逻辑单元数组，每个单元保存字符、颜色和占位状态。应用先在内存中画完整帧，再由编码器生成宽字符 VT 输出，最后用 `WriteConsoleW` 批量提交。课程不在各个视图中散落 `printf`，也不采用逐字符 Win32 写入。

中文显示规则：

- ASCII 占一列；
- 课程支持范围内的 BMP 常用中文占两列；
- 第二列标记为 continuation，VT 编码时不重复输出字符；
- 所有绘制原语先做边界检查；
- 本课程不承诺 emoji、复杂组合字符或完整 Unicode grapheme cluster 排版。

### 4.3 经典控制台事件输入

输入使用 Win32 经典事件模型：

- `ReadConsoleInputW` 读取 `INPUT_RECORD`；
- 处理 `KEY_EVENT` 和 `WINDOW_BUFFER_SIZE_EVENT`；
- 在控制台输入句柄上等待，并用超时返回驱动动画；
- 上层只接触自定义的 `KeyEvent`，不直接依赖虚拟键码。

控制台模式必须：

- 设置 `ENABLE_EXTENDED_FLAGS` 后关闭 `ENABLE_QUICK_EDIT_MODE`；
- 关闭行输入和回显；
- 关闭 `ENABLE_PROCESSED_INPUT`，由应用自己处理 Ctrl+C；
- 保存原始输入输出模式，并在所有退出和初始化失败路径恢复。

### 4.4 UTF-8 持久化与替换式崩溃保护

内存和 Windows 控制台接口使用 `wchar_t`。磁盘文件固定为 UTF-8，由可测试的 codec 明确编码和解码，不依赖当前系统代码页。

数据使用一个累计快照文件：

```text
data/canteen.tsv
```

使用单文件的原因是一次推荐定格会同时更新菜品统计和历史记录。将它们拆成两个文件无法用一次替换保持一致。

保存流程固定为：

1. 将完整新模型序列化到目标目录中的唯一临时文件；
2. 对标准流调用 `fflush`；
3. 由 `store_win32` 取得文件句柄并调用 `FlushFileBuffers`；
4. 关闭临时文件；
5. 对临时文件执行一次完整解析和模型校验；
6. 目标存在时用 `ReplaceFileW` 替换，首次保存时使用带写穿语义的 `MoveFileExW`；
7. 替换失败时保留旧文件，并向应用层返回明确错误；
8. 只有替换成功后，应用才提交新的内存模型。

这是一种替换式崩溃保护：保存过程绝不先截断当前有效文件，也不夸大为跨所有文件系统条件的事务数据库。

## 5. 数据模型

```c
typedef uint64_t DishId;
typedef uint64_t CategoryId;
typedef uint64_t TagId;

typedef struct {
    DishId id;
    wchar_t *name;
    CategoryId category_id;
    VecTagId tag_ids;
    wchar_t *note;
    bool favorite;
    int rating;                 /* 0 表示未评分，1–5 表示有效评分 */
    int64_t lastRecommendedAt;
    uint64_t recommendCount;
    int64_t lastAcceptedAt;
    uint64_t acceptCount;
} Dish;

typedef struct {
    CategoryId id;
    wchar_t *name;
} Category;

typedef struct {
    TagId id;
    wchar_t *name;
} Tag;

typedef enum {
    HISTORY_RECOMMENDED,
    HISTORY_ACCEPTED,
    HISTORY_VIEWED,
    HISTORY_CREATED,
    HISTORY_UPDATED
} HistoryAction;
```

历史记录还要保存发生时间、菜品 ID、菜名快照、分类条件快照、标签条件快照和动作类型。历史容量由设置项控制，追加后从最旧记录开始滚动丢弃。

分类 ID `0` 保留为“未分类”。删除分类时引用它的菜品全部转为 `0`；删除标签时从所有菜品的标签 ID 向量中摘除。所有实体使用稳定 ID，不能把动态数组下标当作持久化 ID。

## 7. 15 章课程表

表中每一章均占 5 场：先完成 1 个概念理解课，再完成 3 个完整引导课，最后进行 1 个受限独立检查。概念理解课先让学习者观察真实现象，再建立心智模型、解释术语和代码位置，并通过两道理解题；独立检查发生在引导完成、主线功能已经可用之后。

## 8. 每章概念理解课与引导课必须包含的内容

概念理解课不能只是术语列表。它必须把本章即将使用的新概念放进一条可理解、可验证的因果链中，并至少包含：

```text
learningGoal            学完后能够用自己的话说明什么
phenomenon
  title                 先观察的具体现象或故障
  observation           学习者能够看到的表现
  question              带着什么问题进入解释
mentalModel
  summary               一段不依赖术语堆砌的整体模型
  flow[]                按因果或数据流排列的步骤与解释
terms[]
  term                  本章代码会出现的术语
  plainMeaning          面向初学者的白话含义
  codeMapping           术语在文件、类型、字段或函数中的位置
workedExample           一个从输入到结果的完整推演
misconceptions[]        常见误解及对应纠正
checks[]                至少两道使用稳定选项 ID 的理解题
bridgeToCode            概念如何落到紧随其后的代码步骤
```

学习者每次只看到当前理解阶段。答题由服务端依据 `correctOptionId` 判定并保存；答错时显示原因，答对后仍保留解释供阅读。全部理解题通过后才显示本章代码、编译步骤和独立检查。概念题只确认理解，不直接发经验、星星或完成章节。

课程数据不能继续只用一句 `guidedBuild` 表示整章。每个引导课至少需要：

```text
starterSnapshot         上一课完成态源码
filesTouched[]          本课会修改的文件
experience              先运行并观察的目标行为
explanation             只解释本课马上会使用的概念
guidedEdits[]
  file                  文件路径
  anchor                插入或替换位置
  code                  可直接使用的完整代码段
  why                   这一段解决的具体问题
buildCommand            本课实际构建命令
runActions[]            可重复的操作步骤
expectedResult          屏幕或文件的明确预期
commonFailures[]        症状、原因和检查位置
solutionSnapshot        本课完成态完整源码
```

长代码放在版本化课程资源目录，课程 JSON 保存资源引用、摘要和校验值，避免把数千行源代码重复内嵌到索引文件。

每个受限独立检查还需要：

```text
task                    一个已经教过的迁移任务
constraints[]           允许修改的文件和禁止改变的合同
acceptance[]            可自动或人工复现的验收条件
evidence[]              构建输出、屏幕状态、文件内容或测试记录
equivalentVariants[]    查看答案后可改派的等价新变式
```

独立检查通常控制在 10–40 行有效修改内。产品主线的完整模块必须先由引导课构建，不能把“实现整个推荐引擎”“自行完成所有 CRUD”伪装成独立检查。

## 9. 可运行里程碑

1. **终端外壳：**安全进入、退出和恢复控制台。
2. **静态食堂：**Frame→VT→`WriteConsoleW` 显示完整中文界面。
3. **可导航食堂：**按键、超时、resize 和视图栈协同工作。
4. **内存菜单：**真实数据模型替代假数据。
5. **可恢复菜单：**UTF-8 文件可以安全保存、载入和迁移。
6. **基础推荐：**分类与标签范围内可得到合法结果。
7. **核心体验：**抽奖动画、接受、收藏和重抽完整可用。
8. **完整管理：**菜品、分类和标签可增删改查。
9. **可解释推荐：**历史、排除最近、去重和加权策略完整。
10. **发布候选：**通过综合故障、内存和崩溃保护检查。

## 10. Boss：午餐高峰开餐验收

Boss 在学习者完成第 15 章独立检查并取得全部 15 颗章节星星后单独解锁，四个阶段各占 1 场。Boss 不增加新功能。系统提供第 15 章完成态候选版本、固定数据包、故障注入开关和验收脚本。学习者独立复现、定位和修复，提示阶梯仍可使用。

### 阶段一：数据开门检查

输入数据同时包含合法记录、转义字符、损坏行、重复 ID、未知引用和超长字段。

通过条件：

- 合法快照完整载入；
- 损坏数据给出行号和原因，不污染当前内存；
- 未知 schema 明确拒绝，已支持旧 schema 正确迁移；
- 历史容量和所有关联 ID 满足模型合同。

### 阶段二：午餐高峰推荐

按指定步骤使用“川菜 + 下饭 + 排除最近 7 天 + 去重”，连续重抽直至轮次耗尽，中途收藏一道菜，再切换为加权策略并接受最终结果。

通过条件：

- 每个定格结果各产生一次 `RECOMMENDED`；
- 视觉预览不增加推荐次数；
- Esc 重抽不产生 `ACCEPTED`；
- Enter 恰好产生一次 `ACCEPTED`；
- 去重轮次、筛选切换、收藏权重和历史记录全部一致。

### 阶段三：终端与保存故障

抽奖过程中连续改变窗口尺寸，并分别在临时文件写入、校验和替换阶段注入失败，最后通过 Ctrl+C 退出。

通过条件：

- resize 后界面重建且状态机不跳转；
- 任一保存失败都保留旧文件；
- 保存失败不会把尚未落盘的新模型伪装成成功状态；
- 程序退出后控制台模式、屏幕和光标恢复；
- 没有未释放的 Frame、视图或模型内存。

### 阶段四：发布验收

完成一次从空数据到正常营业的完整演示：创建分类和标签、录入菜品、组合筛选、推荐、重抽、收藏、接受、查看历史、删除关联项并重新启动。

通过条件：

- 空菜单、空筛选、重复名称和删除关联项都有明确反馈；
- 重启后菜品、设置、统计和历史一致；
- `/W4` 构建没有本课程代码造成的新警告；
- 自动测试全部通过；
- 学习者能解释 Frame 渲染、经典事件输入、推荐过滤、权重区间和替换式保存分别解决什么问题。

Boss 故障清单：

```text
quick-edit-freeze
cjk-right-edge
resize-during-roll
empty-filter-result
duplicate-name
dangling-category
tag-delete-detach
history-over-capacity
no-repeat-cycle-reset
weighted-boundary-hit
malformed-schema
replace-after-flush-failure
memory-allocation-failure

```

完成 Boss 后授予“蛋仔食堂营业执照”战利品，并在成就墙记录“蛋仔食堂正式营业”。
