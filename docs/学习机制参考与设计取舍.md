# 蛋仔编程乐园：学习机制参考与设计取舍

日期：2026-10-13。本文记录当前课程为什么这样设计，防止后续维护重新变成“先展示大量内容，再要求提交作业”的工作台。

## 参考了什么

- [Brilliant 的教学方法](https://brilliant.org/about/)强调一课聚焦一个概念、先让学习者动手、再给即时且有针对性的反馈，并让问题逐步增加难度。它也明确提出游戏化只应支撑学习内容，而不应压过内容本身。乐园据此采用“一屏一步”的预测、运行、解释、修改和独立变式循环。
- [Brilliant Learning Paths](https://brilliant.org/help/features/what-are-learning-paths/)用有顺序的课程路径把核心概念连接到进阶问题，并在路径中设置练习检查点。乐园据此把零散项目改为九阶段位主线，同时保留每个段位内部的明确前置关系。
- [Khan Academy 的 mastery levels](https://support.khanacademy.org/hc/en-us/articles/5548760867853--How-do-Khan-Academy-s-Mastery-levels-work)把“尝试过、熟悉、熟练、掌握”区分开，避免一次做对就等同于长期掌握。[Khan Academy 对 levels 的说明](https://support.khanacademy.org/hc/en-us/community/posts/28945393485581-Update-Introducing-Streaks-and-Levels)则把大课程切成可庆祝的小里程碑。乐园吸收“进度可见”和“综合复用后再晋段”，但不采用掉段或扣除已得奖励。
- [Codecademy Projects](https://www.codecademy.com/projects)把项目分成有较多引导的练习项目和更独立的作品项目，用项目来应用技能、连接概念并形成自己的成果。乐园据此让前三段先完成网页内互动，鹅蛋以后每段只做一件与该段技术绑定的作品。
- [Duolingo 的产品说明](https://blog.duolingo.com/duolingo-101-how-to-learn-a-language-on-duolingo/)展示了 XP、里程碑和成就如何提供持续反馈；[其成就设计](https://blog.duolingo.com/achievement-badges/)把奖励集中陈列成长期可回看的收藏。乐园据此采用经验、等级、段位信物和荣誉墙，但不采用排行榜或强制连续学习。

这些产品提供的是交互与反馈机制参考，不是课程内容模板。当前课程的 C/C++、STM32、Linux、并发、网络、SQL 与 SQLite 顺序仍由学习目标和作品依赖决定。

## 当前采用的学习闭环

每次打开关卡，只出现当前一步：

1. 先在乐园场景中看见一个具体问题；
2. 在运行前做预测；
3. 在网页内真实运行 C 程序并观察结果；
4. 用自己的话解释原因；
5. 在有限范围内修改代码；
6. 立即得到与实际输出对应的反馈；
7. 独立完成一个未见过的等价变式；
8. 在后续关卡、Boss 或作品中再次使用同一能力。

奖励与学习证据分开承担不同作用：

| 机制 | 证明什么 | 不证明什么 |
|---|---|---|
| 经验 | 发生了有意义的练习或探索 | 已经独立掌握 |
| 星星 | 首次独立完成未曝光变式或作品章节 | 整个段位已经融会贯通 |
| Boss | 能组合本段能力处理综合情境 | 后续真实工程一定正确 |
| 段位信物 | 已通过该段晋段条件 | 可以跳过后续复现 |
| 作品战利品 | 留下了可运行、可解释、可回看的成果 | 源码、硬件和故障场景已经由平台自动验证 |

## 针对本项目做的创新

### 看过答案后仍有一条公平的回归路径

完整解法不会扣除已有经验或星星，也不会制造失败惩罚。当前变式在看过解法后不再授星，系统立即分配未曝光的等价变式；学习者独立完成新题后仍能获得星星。这既允许求助，也保留“独立迁移”这条证据。

### 游戏化奖励绑定真实学习行为

经验来自有效练习，星星来自独立迁移，信物来自综合挑战，作品本身成为战利品。重复点击、重复提交和重新播放不能无限刷经验。荣誉墙集中展示已经发生的突破，而不是用大量虚拟货币遮盖学习状态。

### 一段技术对应一件作品

课程不再同时拉动多个长期项目。鹅蛋到无敌凤凰蛋各有一件作品，作品章节与该段技术一一对应；完成一个章节就能看到作品能力增长，最后由 Boss 组织异常场景和综合要求。

### 故事负责记忆，检查点负责严谨

建筑和道具让抽象概念有稳定的记忆位置，例如传送球表示两阶段状态，摩天轮表示实时安全控制，游戏厅表示联网积分与持久化。项目页面同时保留测试清单、证据、失败场景和管理端回看，避免故事包装取代工程要求。

### 节奏允许真正休息

本周游玩卡只安排一个主目标和一个可选短关卡。休息周不会产生欠课、补做、掉星或段位回退。这里有意没有采用每日连续打卡和排行榜，因为当前只有一位学习者，制造损失压力会重新带来“交差感”。

### AI 是分层提示之后的外部教练

页面先提供三层提示，再允许复制当前目标、代码、错误、实际结果和已尝试方法到外部 AI 平台。聊天正文不回写学习档案；回到乐园后仍需预测、解释或完成新变式，避免把“获得答案”误记为“已经掌握”。

## 明确不采用的模式

- 不在一个视口堆完整讲义、全部任务和所有验收表；
- 不用连续登录天数、排行榜或扣星制造焦虑；
- 不把观看、复制答案或重复提交包装成掌握；
- 不让经验值代替独立变式和 Boss 证据；
- 不把后六段的人工自检宣称为平台已经自动验证源码或硬件；
- 不让蛋仔风格压过代码、输出、检查点和错误信息的可读性。

## 后续应观察的信号

当前只有一位学习者，不需要复杂埋点。管理端已有的尝试记录足以回答最重要的问题：

- 打开页面后能否迅速开始第一步；
- 最常卡在哪个步骤，提示通常展开到第几层；
- 看过完整解法后，能否在新变式中重新完成；
- 哪些概念在 Boss 或作品中仍解释不清；
- 一周节奏是否让人愿意回来，而不是产生补课压力；
- 每个作品是否留下可复现的运行证据、故障记录和下一步。

如果这些信号变差，应先调整步骤粒度、反馈和前置知识，再考虑增加新的奖励或动画。
