# 蛋仔岛夜班巡检台完整课程大纲

## 1. 课程定位

“蛋仔岛夜班巡检台”是恐龙蛋段位的唯一累计作品。学习者使用 Linux C17，在同一个工程中从第一条可观察的系统调用开始，逐步完成一个多进程巡检监督系统。

闭园后，中央喷泉总控台要同时派出独立巡检进程检查摩天轮、游戏厅和商城，持续接收报告，并在卡死、崩溃、坏消息、资源耗尽或总控自身重启后给出可解释结果。学习者将在同一个 Linux C 工程中，从第一条系统调用开始，逐章完成一个真正依赖操作系统进程隔离、文件描述符、IPC、事件等待、信号和恢复机制的监督系统。

乐园建筑只承担作品背景。概念课直接观察 PID、进程树、虚拟地址、文件描述符、管道端点、返回值、errno、信号、单调时间、日志与快照。学习者要能从用户态、内核态、进程、文件描述符、IPC、信号和持久化边界解释系统，而不是只记 API 名称。

## 2. 课程目标

完成课程后，学习者应能：

1. 区分程序文件、进程、C 库、系统调用、用户态和内核态，并用 strace 把 C 代码映射到真实系统调用。
2. 用“fd 编号 → 进程描述符表 → 内核对象”解释文件、终端、管道和 FIFO，正确处理短读写、EINTR、EAGAIN、EOF 与 EPIPE。
3. 使用 fork、execve 和 waitpid 建立、替换、跟踪并回收多个子进程，区分启动失败、业务非零、信号终止和僵尸进程。
4. 设计有版本和长度上限的管道帧协议，对任意拆分、粘连、截断和坏帧做增量解析。
5. 用 poll 在一个事件循环中公平处理多个 worker 报告、控制 FIFO、信号桥和 deadline，空闲时不忙循环。
6. 把异步信号限制在异步信号安全的最小操作中，由普通控制流完成回收、日志和清理。
7. 用单调时钟和绝对 deadline 建立有界超时，对独立进程组先 SIGTERM、宽限后 SIGKILL，并完成回收。
8. 用 fd 白名单、工作目录、环境白名单、umask 和 rlimit 缩小 worker 权限与故障影响。
9. 用追加式事件日志、原子快照、故障分类、有限重试和重启对账，在 patrold 崩溃后恢复到可解释状态。
10. 用 strace、ps、/proc/<pid>/fd、退出状态、进程组和故障注入证据证明实现遵守真实操作系统合同。

## 3. 为什么这是操作系统工程，而不是普通编程题

普通编程题可以在一个进程内顺序调用函数，再比对最终文本。本课程的正确性依赖真实 Linux 内核状态：

- patrold、patrol-worker 和 patrolctl 必须是三个独立可执行程序，不能用单进程函数调用冒充进程隔离。
- PID、PPID、PGID、退出方式、僵尸状态和调度顺序由内核维护，不是数组中的模拟字段。
- 报告通道是有容量、有背压、没有消息边界的内核管道。EOF 取决于所有写端引用是否真正关闭。
- poll 必须等待真实就绪事件并处理公平性；不能轮询普通变量或用 sleep 掩盖阻塞。
- SIGCHLD、SIGTERM、SIGINT 和 EINTR 会与普通控制流异步交错，必须遵守异步信号安全边界。
- fd 继承、FD_CLOEXEC、文件锁、单调时钟、rlimit、fsync 与 rename 都有不可由相同打印文本替代的内核语义。
- “worker 退出 0”“收到完整结果帧”“子进程已回收”“结果已持久提交”是四个不同事实。

因此，只输出预期文字、伪造 trace、在单进程中调用所谓 worker 函数，或者只跑一条正常路径，都不构成完成。

## 6. 最终系统架构

~~~text
patrolctl
   │ status / stop / reload
   ▼
run/patrol.ctl (0600 FIFO)
   │
   │       SIGCHLD / SIGTERM / SIGINT
   │                    │
   │                    ▼
   └────────▶ patrold 的 poll 事件循环 ◀── self-pipe 信号桥
                          │
              ┌──────────┼──────────┐
              ▼          ▼          ▼
        report pipe A  report pipe B  report pipe C
              ▲          ▲          ▲
              │          │          │
       patrol-worker  patrol-worker  patrol-worker
        (ferris)       (arcade)        (mall)
              │          │          │
        独立 PGID    独立 PGID    独立 PGID
        受控 fd / cwd / env / umask / rlimit

patrold 事件 ──▶ var/patrol.journal
             └──▶ 原子替换 var/patrol.snapshot
~~~

工程的主要组件为：

- supervisor/main：程序入口、启动、恢复、事件循环与停机编排；
- worker/main：独立巡检程序入口；
- patrolctl：通过受控 FIFO 查询、停止或重载；
- protocol：有版本、有长度上限的本地帧协议；
- spawn 和 SpawnProfile：fork/exec、fd 继承、环境与资源边界；
- event_loop：poll 源、公平预算、控制、信号和 deadline；
- state 和 journal：唯一监督状态入口、追加日志和原子快照。

## 7. 教学循环

12 章共同修改同一个工程，不拆成互不相关的小项目。每章采用固定结构：

1. 先运行一个可观察的 Linux 现象，不先背系统调用名称。
2. 用进程/内核对象图和网页概念模块建立心智模型。
3. 完成三道服务端判定的理解题，并看懂错误选项原因。
4. 跟随三个完整工程增量；每步都构建、运行并采集真实系统证据。
5. 同时验证正常、边界、异常与中途失败。
6. 完成只使用已教授机制的独立变式，保存代码 snapshot 和证据。
7. 后续章节在更复杂的进程拓扑和故障组合中重新使用该能力。

引导过程获得经验；概念题不发星；章末独立变式首次完成获得 1 颗星。Boss 不增加新 API 或新功能，只要求独立整合、诊断并证明已学机制。

## 8. 十二章路线

| 章 | 阶段 | 章节 | 可运行里程碑 |
|---:|---|---|---|
| 1 | 程序与内核 | 一行 C 代码怎样越过用户态 | patrold --probe 能打开配置、输出诊断，并把每次失败还原为具体系统调用与 errno |
| 2 | 文件与状态 | 同一个数字为什么能代表文件、终端和管道 | 日志和报告都通过统一 fd I/O 层传输，重定向后无需改业务代码 |
| 3 | 文件与状态 | 名字、权限和落盘不是一回事 | 第二个 patrold 无法同时占用同一运行目录，状态保存中途崩溃也不破坏上一个完整快照 |
| 4 | 进程与执行 | 一次 fork 为什么会出现两个返回者 | 父进程能派出一个隔离 worker，双方 PID、变量变化和执行分支均可用证据解释 |
| 5 | 进程与执行 | 让子进程换成真正的巡检程序 | patrold 能启动独立 patrol-worker 可执行文件，参数无 Shell 注入，未授权描述符不会穿过 exec |
| 6 | 进程与执行 | 子进程退出后为什么还会留下僵尸 | 总控台能回收任意顺序结束的 worker，不遗留僵尸，并准确区分正常、非零与信号终止 |
| 7 | 进程间通信 | 管道没有消息边界，报告怎样不粘包 | 多个 worker 可发送任意长度和任意切片的结构化报告，父进程能判定完整、截断和 EOF |
| 8 | 事件循环 | 一个线程怎样同时照看所有巡检员 | 一个慢 worker 不能阻塞其他报告，patrolctl 的 status/stop/reload 命令能与报告并发处理 |
| 9 | 异步控制 | 信号到达时为什么不能直接做完整清理 | 信号处理函数只产生最小通知，普通控制流完成回收与清理；重复停止和信号风暴不会重入破坏状态 |
| 10 | 异步控制 | 超时不是 sleep 之后再看看 | 每个任务和全局批次都有可证明期限；系统墙钟跳变不影响超时，worker 的后代进程不会遗留 |
| 11 | 监督与恢复 | 一个坏巡检员怎样被限制在自己的边界里 | worker 只能看到明确授权的 fd 与运行上下文，打开文件、CPU 和地址空间超限不会拖垮总控台 |
| 12 | 监督与恢复 | 让总控台在真实故障后仍能恢复 | 完整 patrold 可并发巡检、响应控制、隔离故障、在崩溃重启后解释并继续未确认任务，所有进程与 fd 有界收束 |

### 第 1 章：一行 C 代码怎样越过用户态

- **目标：**从程序文件、进程、C 库、系统调用和内核职责开始，第一次用 strace 证明用户程序如何请求操作系统服务。
- **概念：**用户态与内核态、系统调用、进程、errno。
- **工程主线：**从一个只会打印文字的 C 程序起步，建立 patrold 骨架、统一错误对象和最小 strace 观察流程。
- **工程增量 1｜建立可追踪的 Linux C 工程：**创建 patrold 可执行目标，支持 --probe；打印 PID 与启动阶段，main 只协调初始化、运行和退出码。
  - 验证：Debug 构建无警告，--probe 返回 0，输出中的 PID 与 ps 观察一致。
- **工程增量 2｜保存失败现场而不是猜错误：**实现 OsError，系统调用失败后第一时间保存 operation、errno 和上下文；日志稍后再格式化。
  - 验证：打开缺失配置时显示 open、ENOENT 和路径；制造 EACCES 时原因不同，退出码非零。
- **工程增量 3｜把 C 行为映射到系统调用：**加入错误对象测试，并用 strace -f -yy -o trace.log 运行 --probe，标出 execve、openat、read、write 与 exit_group。
  - 验证：测试通过；trace.log 中的关键调用可与程序阶段逐一对应，程序本身不解析或伪造 trace。
- **独立变式：**增加 --probe-missing：真实尝试打开一个不存在路径，保存 errno 并返回约定退出码；不得根据字符串直接打印 ENOENT。
- **学习证据：**程序输出、退出码与包含失败 openat 的 strace 摘要
- **自动检查合同：**real-syscall、errno-captured-immediately、distinct-exit-code。
- **后续重遇：**下一章会发现系统调用返回的非负小整数不是文件本身，而是进程描述符表中的编号。

### 第 2 章：同一个数字为什么能代表文件、终端和管道

- **目标：**理解文件描述符表和打开文件描述，写出能处理短读写、EOF 与 EINTR 的通用字节流函数。
- **概念：**文件描述符、进程描述符表、打开文件描述、短读写、EOF 与 EINTR。
- **工程主线：**实现 os_read_some、os_write_all 与 fd_logger，并用小块注入测试证明代码不假设一次读写完成。
- **工程增量 1｜写出不撒谎的字节流接口：**定义 IoResult，分别表达 bytes、EOF 与 error；实现 read_some，并只在 EINTR 时按策略重试。
  - 验证：空文件得到 EOF；大文件跨多次读取；非 EINTR 错误保留原 errno。
- **工程增量 2｜循环完成短写：**实现 write_all；测试替身强制每次只写 1–7 字节，并在中间注入 EINTR。
  - 验证：完整字节序列无缺失无重复；0 进展和 EPIPE 都能结束而不死循环。
- **工程增量 3｜让日志后端只依赖 fd：**实现 fd_log_write(level,message)，默认写 stderr；不在日志模块打开固定路径。
  - 验证：直接运行时日志出现在终端，2>build/error.log 后同一代码写入文件。
- **独立变式：**实现 copy_fd(src,dst)，在输入大于缓冲区、空输入、注入 EINTR 和每次短写时都精确复制；禁止使用 stdio 一次性读全文件。
- **学习证据：**二进制哈希对比、I/O 调用序列与 /proc/self/fd 快照
- **自动检查合同：**empty-stream、multi-read-write、eintr-resume、no-byte-duplication。
- **后续重遇：**管道通信、控制 FIFO、日志文件和持久化快照都会继续使用同一套 fd 与短读写模型。

### 第 3 章：名字、权限和落盘不是一回事

- **目标：**理解路径解析、inode、权限、open 标志、原子替换和目录锁，为巡检台建立可恢复的运行目录与状态快照。
- **概念：**路径与 inode、open 标志、权限与 umask、原子替换与 fsync、建议锁。
- **工程主线：**建立 config、run、var 三类目录，使用 O_CREAT/O_EXCL、flock、临时文件、fsync 与 rename 管理单实例和快照。
- **工程增量 1｜建立受控运行目录：**以目录 fd 为边界创建 run 与 var，设置明确 umask，使用 openat/mkdirat，拒绝符号链接替换关键文件。
  - 验证：首次启动创建权限正确的目录；已有目录可重入；关键路径是符号链接时拒绝继续。
- **工程增量 2｜让单实例由内核锁保证：**打开 run/patrold.lock 并持有 flock；把 PID 作为诊断内容，不把 PID 文本当作互斥本身。
  - 验证：第二个进程立即得到“已有实例”并退出；杀掉首实例后锁自动释放，即使文件仍存在。
- **工程增量 3｜保存可恢复快照：**实现同目录临时文件、完整写入、fsync、rename 和父目录 fsync；为每个步骤提供故障注入点。
  - 验证：在创建、写入、fsync、rename 前注入失败，重启总能读到完整旧版或完整新版，没有半文件。
- **独立变式：**增加状态文件 schema_version，并实现一次 v1→v2 原子迁移；未知未来版本必须只读拒绝，不能覆盖。
- **学习证据：**故障矩阵、每次重启后的文件哈希、权限与锁竞争日志
- **自动检查合同：**single-instance、atomic-replace、directory-fsync、future-version-rejected。
- **后续重遇：**最终监督器会把任务状态写入同一日志与快照，并在自身崩溃后据此恢复。

### 第 4 章：一次 fork 为什么会出现两个返回者

- **目标：**从虚拟地址空间和写时复制理解 fork，让总控台首次派出独立巡检员且不重复执行父进程职责。
- **概念：**程序与进程、虚拟地址空间、fork 返回值、写时复制、调度顺序。
- **工程主线：**在 patrold 中建立 WorkerSlot，fork 一个 worker；用管道前的临时日志和 /proc 证据观察父子分支、地址相同与数据隔离。
- **工程增量 1｜建立 WorkerSlot 与单个 fork：**定义 EMPTY/STARTING/RUNNING 槽位；fork 后子分支只进入 worker_probe，父分支记录 PID，失败不污染槽位。
  - 验证：父子各输出一次带 PID/PPID 的记录；父进程不执行 worker 任务，子进程不继续总控初始化。
- **工程增量 2｜观察虚拟内存隔离：**让父子修改 fork 前变量并记录虚拟地址和值；用 /proc/<pid>/maps 或资源统计辅助观察。
  - 验证：地址可相同而最终值不同；测试不依赖输出顺序，且解释写时复制边界。
- **工程增量 3｜派出多名巡检员但不复制总控工作：**循环创建三个 worker，每次子分支立刻进入专用入口并 _exit；父进程只登记成功创建的 PID。
  - 验证：三名 worker 各报告一次；总控启动日志只有一份；任意一次 fork 失败时已创建子进程仍可管理。
- **独立变式：**把 worker 数量改为配置驱动的 1、3、8 三组，并证明 fork 中途失败时不会把未创建槽位标为 RUNNING。
- **学习证据：**进程树、每个分支一次性日志、变量地址和值对照与失败注入结果
- **自动检查合同：**configured-worker-count、no-duplicate-parent-work、fork-failure-consistent。
- **后续重遇：**下一章用 exec 把临时内联 worker 替换为真正独立的巡检程序。

### 第 5 章：让子进程换成真正的巡检程序

- **目标：**理解 exec 替换进程映像但保留 PID 的机制，安全传递 argv、受控环境和必要 fd，并区分 exec 失败与巡检失败。
- **概念：**exec 进程映像替换、argv 与环境变量、描述符继承、FD_CLOEXEC。
- **工程主线：**新增 patrol-worker 可执行程序；父进程在 fork 前准备通信 fd，子进程整理描述符与环境后 execve，失败使用保留错误通道和 _exit。
- **工程增量 1｜拆出独立 patrol-worker：**新增 worker 目标，解析 --site 与 --report-fd；先输出固定健康报告并返回 0，非法参数返回 64。
  - 验证：worker 可单独运行测试；同一建筑名含空格时保持一个 argv 元素。
- **工程增量 2｜建立安全 spawn 边界：**实现 pipe2(O_CLOEXEC) + fork + execve；子进程只保留约定报告 fd，使用绝对路径和环境白名单。
  - 验证：/proc/<pid>/fd 显示 worker 没有锁 fd、快照 fd和其他 worker 管道；PID 在 exec 前后不变。
- **工程增量 3｜区分启动失败和业务失败：**保留独立 exec-error 管道；失败时传 errno 并 _exit(126)，成功时该管道因 CLOEXEC 自动 EOF。
  - 验证：缺失可执行文件记录 START_FAILED/ENOENT；worker 返回 2 记录 EXITED_NONZERO，其他 worker 照常启动。
- **独立变式：**增加一个名称含空格和分号的站点；证明它仍是单一 argv，不会启动额外命令，并验证 worker 只继承三个标准 fd 与报告 fd。
- **学习证据：**strace execve 参数、/proc/<pid>/fd 清单与启动失败/业务失败状态表
- **自动检查合同：**argv-boundary、no-shell-injection、cloexec-clean、exec-failure-distinct。
- **后续重遇：**下一章用 waitpid 读取这些子进程真正的退出方式并消除僵尸。

### 第 6 章：子进程退出后为什么还会留下僵尸

- **目标：**掌握 waitpid 与退出状态编码，完整维护 STARTING、RUNNING、EXITED、SIGNALED 和 REAPED 生命周期。
- **概念：**waitpid、退出状态、僵尸进程、孤儿进程、非阻塞回收。
- **工程主线：**为 WorkerSlot 加入生命周期和不可逆转移；用 waitpid(-1,...,WNOHANG) 循环回收全部已退出子进程并保留诊断。
- **工程增量 1｜定义不可逆生命周期：**定义 STARTING→RUNNING→EXITED/SIGNALED→REAPED 转移，保存 PID、开始时间、原始与解码结果。
  - 验证：非法回退和重复回收被拒绝；每次转移有单一日志。
- **工程增量 2｜循环回收所有已结束子进程：**实现 WNOHANG 回收循环，正确处理 0、EINTR、ECHILD 和未知 PID；一次调用收完当时所有结束项。
  - 验证：同时结束 20 个 worker 后无僵尸；EINTR 不丢状态，未知 PID 记录诊断但不越界。
- **工程增量 3｜把终止方式变成业务可读结果：**用 WIF*/W* 宏生成 PASSED、FAILED_EXIT、FAILED_SIGNAL；保留信号编号和 core 标志。
  - 验证：exit 0、exit 2、SIGSEGV、SIGTERM 均分类正确；业务代码不直接读取 raw status。
- **独立变式：**启动 20 个以随机顺序退出的 worker，其中包含 0、非零和信号终止；结果计数准确且最终 waitpid 返回 ECHILD。
- **学习证据：**退出分类表、ps 前后对照、waitpid 调用序列与最终 ECHILD 证据
- **自动检查合同：**mixed-exits、all-reaped、status-decoded、no-zombie。
- **后续重遇：**报告管道关闭与进程退出可能以不同顺序发生，下一章要同时管理两条生命周期。

### 第 7 章：管道没有消息边界，报告怎样不粘包

- **目标：**理解管道的字节流、端点引用、EOF、PIPE_BUF 和 SIGPIPE，设计可分帧、可增量解析的 worker 报告协议。
- **概念：**匿名管道、字节流与消息帧、管道 EOF、PIPE_BUF、SIGPIPE。
- **工程主线：**定义固定头部 + 长度载荷协议，为每个 worker 建立独立报告管道和增量接收缓冲，严格关闭所有无用端点。
- **工程增量 1｜定义有上限的报告帧：**定义版本、类型、task_id、payload_len 的网络无关本地协议；长度有硬上限，解析器不依赖结构体内存布局直接传输。
  - 验证：1 字节切片、整帧、两帧粘连和非法超长都得到确定结果。
- **工程增量 2｜为每个 worker 接入报告管道：**spawn 前创建管道；父进程只留读端，worker exec 后只留约定写端；worker 用 write_all/send_frame 发送 STARTED 与 RESULT。
  - 验证：/proc fd 拓扑符合设计；正常 worker 的两个帧完整到达并最终 EOF。
- **工程增量 3｜识别截断、坏帧和读者离开：**EOF 时验证缓冲为空；非法版本、超长、半帧进入协议错误；worker 对 EPIPE 明确退出。
  - 验证：半头、半载荷、坏长度和关闭读端均不挂起、不越界，且错误归属正确 worker。
- **独立变式：**让三个 worker 分别按单字节、随机块和一次性写入同样协议；父进程应得到三份等价报告，并在某 worker 半帧退出时仅标记它协议失败。
- **学习证据：**接收切片轨迹、完整帧列表、EOF/残帧状态与 /proc fd 端点表
- **自动检查合同：**fragmented-frames、coalesced-frames、truncated-frame、eof-arrives、no-writer-leak。
- **后续重遇：**下一章用 poll 同时等待多个报告管道和控制通道，而不是轮流阻塞读取。

### 第 8 章：一个线程怎样同时照看所有巡检员

- **目标：**理解阻塞、非阻塞、就绪与背压，用 poll 构建公平事件循环，同时处理多个 worker 管道和控制 FIFO。
- **概念：**阻塞与非阻塞、I/O 就绪、poll、背压、控制 FIFO。
- **工程主线：**把报告 fd 设置非阻塞，建立 PollSource 表、每源缓冲和单轮处理预算；增加 run/patrol.ctl FIFO 与 patrolctl 工具。
- **工程增量 1｜建立可测试的 poll 源表：**定义 source kind、fd、interest、buffer、budget 与回调；处理 POLLIN/HUP/ERR 组合。
  - 验证：空闲时不忙循环；一个源关闭不影响其他源；事件组合不会漏掉尾部数据。
- **工程增量 2｜同时汇聚多个 worker：**所有报告读端设非阻塞并加入循环；每源独立协议缓冲，单轮限制字节和帧数，轮转扫描起点。
  - 验证：慢发、碎片发和高流量 worker 并存时，正常结果都在有界轮数内处理。
- **工程增量 3｜加入 patrolctl 控制通道：**创建 0600 控制 FIFO，解析 status/stop/reload；命令有最大长度和明确回应文件或终端输出，不执行任意文本。
  - 验证：巡检运行中 status 可响应；超长与未知命令被拒绝；控制客户端退出不让总控得到永久 EOF 忙循环。
- **独立变式：**构造一个每次只写 1 字节的 slow worker、持续写 1000 帧的 noisy worker 和一次写完的 normal worker；normal 与 status 必须在有界轮数内完成。
- **学习证据：**每轮 ready 集合、每源处理预算、命令响应时间与空闲 CPU 观察
- **自动检查合同：**slow-source-progress、noisy-source-fairness、control-responsive、no-busy-loop。
- **后续重遇：**信号也会异步改变系统状态，下一章将其转换成事件循环可处理的普通 fd 事件。

### 第 9 章：信号到达时为什么不能直接做完整清理

- **目标：**理解信号的异步执行语义、sigaction、EINTR 与异步信号安全，把 SIGCHLD、SIGTERM、SIGINT 可靠桥接进事件循环。
- **概念：**信号、sigaction、异步信号安全、EINTR、self-pipe。
- **工程主线：**建立 self-pipe 信号桥；处理函数仅写一个字节/设置 sig_atomic_t 标志，event loop 读取后执行 reap、stop 和 reload 状态转换。
- **工程增量 1｜建立最小 self-pipe 桥：**创建 O_NONBLOCK|O_CLOEXEC 管道；处理器只设置 sig_atomic_t 标志并 write 单字节，保存恢复 errno。
  - 验证：静态检查和测试确认处理器不调用 malloc/printf/close-all；满管道时标志仍保留意图。
- **工程增量 2｜把 SIGCHLD 接入回收循环：**收到 child_changed 后循环 waitpid(-1,WNOHANG)，直到 0/ECHILD，再清标志并复查竞态窗口。
  - 验证：多个同时退出只触发一次通知也能全部回收；信号与 poll 交错时无僵尸。
- **工程增量 3｜让停止成为幂等状态转换：**SIGTERM/SIGINT 只请求 RUNNING→STOPPING；后续重复信号不重新释放资源，主循环负责关闭控制入口并启动 worker 停止流程。
  - 验证：连续 50 次停止信号只产生一次清理序列，事件循环最终退出，无双重 close 和崩溃。
- **独立变式：**在 30 个子进程同时退出时连续发送 SIGTERM、SIGINT；全部子进程必须回收，停止状态只进入一次，self-pipe 满时也不能遗失停止意图。
- **学习证据：**信号通知序列、状态转移日志、最终 ps 与资源清理记录
- **自动检查合同：**signal-storm、all-children-reaped、idempotent-stop、handler-async-safe。
- **后续重遇：**下一章把超时也纳入同一个事件循环，并对整个 worker 进程组实施有期限的停止。

### 第 10 章：超时不是 sleep 之后再看看

- **目标：**使用单调时钟和绝对 deadline 计算 poll 等待，对超时 worker 先温和终止再按进程组强制清理。
- **概念：**单调时钟、绝对 deadline、poll 超时、进程组、分级终止。
- **工程主线：**引入 Clock 抽象、最小 deadline 计算、worker 进程组与 TERM→grace→KILL 策略，所有计时共用 event loop。
- **工程增量 1｜建立可测试的单调 deadline：**封装 monotonic now、饱和加法和向上换算 poll 毫秒；测试使用 FakeClock 精确推进。
  - 验证：边界 0、1ms、超长持续时间和多次提前唤醒都不漂移、不溢出。
- **工程增量 2｜让 worker 拥有独立进程组：**fork 后子进程和父进程协同 setpgid，记录 pgid；处理双方竞态与已 exec 情况。
  - 验证：worker 及 helper 位于预期 PGID；任意启动失败不会误杀 patrold 所在组。
- **工程增量 3｜实现 TERM 到 KILL 的有界升级：**任务 deadline 到期发 SIGTERM 组并设 grace；仍未结束则 SIGKILL；回收完成前不复用槽位。
  - 验证：响应 TERM 的任务不收 KILL；忽略 TERM 的进程组在期限内消失；所有直接子进程被 wait。
- **独立变式：**为三个任务设置 80ms、120ms、200ms deadline，其中第二个响应 TERM、第三个派生忽略 TERM 的 helper；验证升级时序和最终进程树。
- **学习证据：**单调时间轴、每次 poll timeout、TERM/KILL 时间点与最终进程组/回收证据
- **自动检查合同：**monotonic-deadlines、no-time-drift、term-before-kill、descendants-contained。
- **后续重遇：**资源限制章节会继续收紧每个进程组能打开的 fd、分配的地址空间与继承的运行环境。

### 第 11 章：一个坏巡检员怎样被限制在自己的边界里

- **目标：**用描述符白名单、工作目录、环境变量、umask 和 rlimit 限制 worker，把泄漏、资源耗尽和越权访问变成可诊断的单任务失败。
- **概念：**最小权限、描述符泄漏、资源限制 rlimit、工作目录与环境、故障隔离。
- **工程主线：**为每类 worker 建立 SpawnProfile；exec 前关闭未授权 fd，设置 cwd/env/umask/rlimit，并用 /proc 与压力 worker 验证隔离。
- **工程增量 1｜定义最小 SpawnProfile：**为普通、文件检查和压力测试 worker 定义 cwd、env 白名单、umask、保留 fd 与 rlimit；启动前验证配置范围。
  - 验证：非法上限、缺失 cwd 和重复 fd 在 fork 前被拒绝，profile 可打印为审计摘要。
- **工程增量 2｜清理继承并应用限制：**子分支只调用安全的预计算步骤：dup2 目标 fd、关闭其余、fchdir、umask、setrlimit、execve。
  - 验证：worker 的 /proc/self/fd、cwd、环境和 getrlimit 与 profile 一致；总控锁与控制 FIFO 未泄漏。
- **工程增量 3｜证明坏任务不会拖垮总控：**增加 open-storm、alloc-storm、cpu-spin 与 crash 模式，验证 EMFILE/ENOMEM/SIGXCPU/SIGSEGV 分类和有界回收。
  - 验证：故障只落在对应 WorkerSlot；正常 worker、status 命令和最终快照继续成功。
- **独立变式：**加入一个试图读取未授权环境变量、持有 100 个 fd 并无限分配的 worker；证明信息未继承、限制生效且 normal worker 完成。
- **学习证据：**SpawnProfile 摘要、worker /proc 与 getrlimit 输出、各任务结果和总控存活证据
- **自动检查合同：**environment-allowlist、fd-whitelist、rlimit-enforced、supervisor-survives。
- **后续重遇：**最后一章把所有状态、重试和持久化证据组合成可在自身崩溃后继续工作的监督器。

### 第 12 章：让总控台在真实故障后仍能恢复

- **目标：**用显式监督状态机、故障分类、有限重试、退避、追加日志和重启对账完成可恢复的夜班巡检系统。
- **概念：**监督状态机、故障分类、有限重试与退避、追加式日志、重启对账。
- **工程主线：**将 worker、报告、deadline、signal、control 和持久化汇入单一状态机；每次不可逆转移先写事件日志，周期性原子快照，重启后对账。
- **工程增量 1｜收束为单一监督状态机：**定义 Supervisor/Task/Attempt 状态和 Event；所有回调只生成事件，apply 验证 task、attempt、前置状态和幂等键。
  - 验证：乱序、重复、旧 attempt 和非法回退被拒绝或幂等忽略；正常完整轨迹得到唯一终态。
- **工程增量 2｜建立可回放日志与快照：**追加带序号、长度和校验的事件，关键边界 fdatasync；原子快照记录 last_sequence，启动检测并处理半条尾记录。
  - 验证：在每个写入字节边界模拟崩溃，恢复结果等于某个完整事件前缀；不重复应用已快照事件。
- **工程增量 3｜完成恢复、重试和发布证据：**启动时持锁、恢复、对账后再接收命令；按故障分类与退避重试；停止时关闭入口、终止组、排空报告、回收、同步并释放锁。
  - 验证：混合正常、非零、坏帧、超时、资源超限和总控崩溃时，最终状态可解释、进程/fd 清零、重启不重复已提交结果。
- **独立变式：**在 STARTED、RESULT_RECEIVED、REAPED、COMMITTED 四个边界分别杀死 patrold 并重启；已提交结果不重复，未确认任务按策略解释且最多重试一次。
- **学习证据：**日志回放摘要、快照序号、各 attempt 时间线、重启前后进程/fd 清单与最终报告
- **自动检查合同：**state-machine-invariants、journal-prefix-recovery、no-duplicate-commit、bounded-retry、clean-shutdown。
- **后续重遇：**Boss 会隐藏故障类型，同时组合管道泄漏、信号风暴、后代进程、资源超限和总控崩溃，要求从系统证据独立定位。

## 9. Boss：全岛闭园巡检总演练

闭园窗口内同时出现：一个 worker 半帧后崩溃，一个持有多余写端导致 EOF 不到，一个派生 helper 后卡死，一个触发 fd 上限，一个正常完成；此时 SIGCHLD 与停止命令交错，总控又在结果提交边界崩溃一次。学习者不得增加新功能，要从系统证据独立定位、修复并完成恢复验收。

Boss 不增加新功能，而是同时打乱已经学过的进程、fd、IPC、信号、时限、资源限制和持久化边界。四个阶段为：

1. **重建进程与描述符现场**
   - 用 ps 与 PID/PPID/PGID 重建进程树
   - 用 /proc/<pid>/fd 标出每条管道和锁的所有者
   - 用 strace 区分阻塞、EINTR、EAGAIN、EOF 与进程退出
2. **修复通信与回收**
   - 半帧只使对应任务失败且其他报告完整
   - 遗留写端关闭后 EOF 有界到达
   - 所有直接子进程被 wait，helper 随进程组收束
3. **承受信号与资源故障**
   - 信号风暴只触发一次幂等停止
   - 资源超限不拖垮总控与正常 worker
   - TERM 到 KILL 的期限由单调时间证明且无忙循环
4. **崩溃恢复与发布验收**
   - 四个持久化边界逐点崩溃后均可重启
   - 已提交结果不重复，未确认结果有明确策略
   - 最终无僵尸、孤儿、fd 泄漏或损坏快照
   - 能从用户态/内核态、进程、fd、IPC、信号和日志六层解释系统

| descendant-ignores-term | PID/PPID/PGID 与 deadline | 宽限后整组 KILL，无 helper 遗留 | 单调时间轴和最终进程树 |
| fd-limit-exhaustion | getrlimit、EMFILE、worker 输出 | RESOURCE_LIMIT；总控与 normal worker 存活 | 限额档案和独立任务结果 |
| worker-segfault | wait status 与 core 标志 | FAILED_SIGNAL/SIGSEGV，有界回收 | WIFSIGNALED 分类和其他结果 |
| journal-tail-tear | sequence、长度与 checksum | 截到最后完整记录边界 | 回放等于完整事件前缀 |
| crash-after-result-before-commit | RESULT_RECEIVED/COMMITTED 日志 | 幂等补完提交，不重跑 worker | 重启前后 attempt 和提交计数 |
| pid-reuse-guard | PID 与 /proc starttime | 不向同号新进程发信号 | 持久身份与当前内核身份对照 |

## 10. 学习证据

每章的证据不是“终端打印了某句话”，而是与该章内核合同对应的证据组：

| 证据类别 | 必须说明什么 |
|---|---|
| 构建与测试 | 干净构建命令、编译器版本、CTest 结果和实际运行的故障组合 |
| 系统调用 | strace 中的关键调用、参数、返回值、errno 与所属 PID |
| 进程拓扑 | PID/PPID/PGID、创建/替换/退出/回收时间线，最终无僵尸和遗留 helper |
| fd 所有权 | /proc/<pid>/fd 前后快照，每条管道/FIFO/锁/日志由谁持有、何时关闭 |
| 协议 | 接收切片、帧解析结果、EOF 时残留缓冲、坏帧归属与隔离 |
| 事件循环 | 每源预算、ready 集、最大响应轮数、空闲 CPU 和无忙循环说明 |
| 信号与时限 | handler 操作清单、信号序列、单调时间轴、TERM/KILL/回收时点 |
| 隔离 | SpawnProfile、worker 实际 fd/cwd/env/umask/rlimit、超限分类和总控存活 |
| 持久化与恢复 | journal sequence/checksum、snapshot 序号、故障点、回放前缀、attempt 与提交计数 |
| 独立解释 | 不依赖完整 AI 解法，能用用户态/内核态、进程、fd、IPC、信号和日志六层讲清一次故障 |

每份证据记录命令、环境、预期、实际、退出码、关键原始摘录和结论。截图可以辅助阅读，但不能替代可复现命令和文本证据。

## 11. 验收边界

本段位验收的是一个可解释、可跟踪、可隔离故障、可有界停止、可从持久证据恢复的 Linux 多进程监督器。必须同时满足：

- Debug 构建无新增警告；12 章测试和 Boss 组合故障均真实执行。
- 正常 worker 不因其他 worker 半帧、卡死、资源超限或信号终止而丢失报告。
- 每个 worker/attempt 有唯一、可追溯的结局；直接子进程全部回收，受控进程组有界消失。
- 不遗留僵尸、未受控 helper、FIFO 写端、锁、管道端点或其他 fd。
- 空闲时不忙循环；高流量源不饿死控制通道与其他 worker。
- deadline 使用单调时钟，TERM→KILL→wait 的总时间有硬上界。
- exit 0、完整结果帧、进程回收和 COMMITTED 不被合并成同一事实。
- 日志损坏尾可检测并收缩到最后完整记录；快照只能是完整旧版或完整新版。
- 已提交结果在重启后不重复；未确认任务可解释、重试有上限，首次失败证据不被覆盖。
- 验收者能从原始系统证据复现结论，而不是只相信学习者填写的完成状态。

本段位明确不做：

- 线程池、互斥锁、条件变量和 C++ RAII；这些属于巅峰凤凰蛋的并发作品。
- TCP/UDP、远程客户端、SQL 与数据库事务；这些在后续段位学习。
- 使用 system、popen 或字符串拼 Shell 命令替代 fork/execve。
- 将 rlimit 宣称为完整安全沙箱；它只是本课程使用的资源边界之一。
- 用网页文字作答、自检勾选或伪造跟踪输出替代真实 Linux 运行。
