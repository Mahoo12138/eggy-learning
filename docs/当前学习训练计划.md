## 学习规则

- 一次只显示一个步骤：观察示例、预测、运行观察、解释、引导操作、即时反馈、独立变式、延后重现。
- 练习获得经验；首次独立完成变式获得星星；综合 Boss 负责晋段。
- 查看完整解法不会扣除已有奖励，但当前变式不再授星，会改派等价新变式。
- 允许休息周，不形成欠课；段位、星星、信物和作品永久保留。

### 4. 鹅蛋

- 技术：C 数组、字符串、结构体、指针、内存、文件与系统化调试
- 作品场景：苹果派雪雪烘焙店、淘气丸子奶茶店
- 晋段奖励：美食街招牌模型

**段位作品：蛋仔食堂·今天吃什么**

蛋仔食堂每天从苹果派雪雪烘焙店和淘气丸子奶茶店收集菜单。学习者要把菜名、分类、库存与选择记录组织起来，让“今天吃什么”可以查询、筛选、随机推荐并在重启后保留数据。

| 章节 | 目标 | 独立检查 |
|---|---|---|
| 把菜单放进数组 | 从固定菜单中安全读取和显示菜品。 | 加入空菜单和满容量菜单用例。 |
| 用结构体描述一道菜 | 把名称、类别和是否售罄组合为一个 Dish。 | 独立增加饮品类别并正确过滤售罄项。 |
| 让函数修改候选状态 | 用指针和清楚的所有权边界拆分选择流程。 | 新增“换一个”且不得重复当前候选。 |
| 让菜名安全进入内存 | 处理长度、终止符和非法文本。 | 验证空名称、恰好上限和超过上限三种输入。 |
| 保存并恢复最近选择 | 以明确格式读写菜单和历史。 | 让只读目录和损坏历史文件都能安全退出或回退。 |
| 用调试器找到越界根因 | 通过断点、变量观察和最小复现定位内存错误。 | 提交修复前后的复现步骤和一条防回归用例。 |

**Boss：美食街闭店前的最后一单** — 菜单已满、历史文件含坏行，保存目录突然不可写；程序仍要给出合法候选并保护旧记录。

### 5. 鸵鸟蛋

- 技术：STM32 裸机、GPIO、定时器、中断、UART、ADC、I²C/SPI 与状态机
- 作品场景：巨型摩天轮
- 晋段奖励：摩天轮中控模型

**段位作品：蛋仔摩天轮安全中控站**

摩天轮需要在按钮、传感器和故障信号共同作用下安全启动、运行、停靠和复位。

| 章节 | 目标 | 独立检查 |
|---|---|---|
| 点亮第一盏安全灯 | 建立工程，读取按钮并控制状态灯。 | 独立增加“未准备好时红灯常亮”。 |
| 消除按钮抖动 | 用非阻塞状态机识别一次稳定按下。 | 连续快速按压不会重复启动。 |
| 用定时器驱动运行节拍 | 配置周期中断并保持中断处理短小。 | 独立实现每 100 个节拍更新一次轿厢位置。 |
| 让中控站会报告自己 | 设计可读且不会淹没串口的状态日志。 | 加入传感器错误码和一次性故障报告。 |
| 接入高度与门锁传感器 | 读取 ADC，并通过 I²C 或 SPI 获取一个外设状态。 | 断开传感器时中控进入故障态而非继续运行。 |
| 完成安全恢复状态机 | 把启动条件、运行、停靠、故障和复位组合起来。 | 任何状态检测到门锁失效都立即停止并锁定故障。 |

**Boss：摩天轮雨夜安全演练** — 按钮发生抖动、计时器接近回绕、门锁传感器中途断开，系统还会被突然复位。

### 6. 恐龙蛋

- 技术：Linux C 系统编程、进程、文件描述符、管道、信号与故障恢复
- 作品场景：中央喷泉广场、巨型摩天轮、游戏厅、商城建筑
- 晋段奖励：夜班巡检灯

**段位作品：蛋仔岛夜班巡检台**

夜间总控台要同时启动多个建筑巡检程序，收集报告，并在子进程故障时留下明确记录。

| 章节 | 目标 | 独立检查 |
|---|---|---|
| 认识总控台的文件描述符 | 用 read/write 处理日志文件并检查短读写。 | 读取空文件和大于缓冲区的报告。 |
| 为建筑派出巡检员 | 用 fork 区分父子进程并记录 PID。 | 创建三个巡检员且每个只报告一次。 |
| 启动真实巡检程序 | 用 exec 替换子进程并用 waitpid 收集退出状态。 | 一个命令不存在时，其他巡检仍正常完成。 |
| 用管道汇总巡检报告 | 创建管道并关闭每个进程不使用的端点。 | 汇总三份不同长度报告且不截断。 |
| 处理中止与超时 | 用信号通知停止，并让阻塞系统调用正确恢复或退出。 | 连续两次停止请求不会重复清理或挂起。 |
| 完成巡检监督器 | 把启动、汇总、超时、重试和退出码组合起来。 | 仅对超时任务重试一次，其他结果不重复。 |

**Boss：全岛闭园巡检** — 一个子进程挂起，一个异常退出，一个忘记关闭管道写端，另一个正常完成。

### 7. 巅峰凤凰蛋

- 技术：C++ 工程、资源管理与多线程并发
- 作品场景：商城建筑
- 晋段奖励：配送中心微缩模型

**段位作品：蛋仔商城道具配送中心**

商城订单不断进入，道具仓库由多个工作人员线程共同处理，必须避免重复发货、负库存和关店死锁。

| 章节 | 目标 | 独立检查 |
|---|---|---|
| 建立订单与库存模型 | 用 string、vector、unordered_map 和值语义表达业务数据。 | 独立增加订单校验并拒绝未知道具。 |
| 让资源自动回收 | 使用 RAII 管理线程、文件和锁的生命周期。 | 在处理中抛出异常仍能关闭日志并回收对象。 |
| 让多个工作人员领取订单 | 创建工作线程并用 join 管理结束。 | 线程数量从配置读取且 0、1、多线程均可运行。 |
| 建立等待式任务队列 | 使用 mutex 和 condition_variable 实现生产者消费者。 | 空队列关店时所有线程都能退出。 |
| 修复共享库存竞态 | 让检查和扣减成为一个原子临界区。 | 1000 组并发订单下库存不为负且成功数正确。 |
| 解除双仓库死锁 | 固定锁顺序并支持任务取消。 | 反向转仓并发 100 次不死锁且总库存不变。 |
| 完成商城安全关店 | 拒绝新订单、处理策略明确，并唤醒所有线程退出。 | 实现“排空队列”和“取消剩余”两种明确策略。 |

**Boss：商城节日前夜配送高峰** — 订单重复到达、库存争抢、转仓反向加锁，营业中途还收到立即关店指令。

### 8. 超级凤凰蛋

- 技术：C 网络编程与 C++/SQL/SQLite 数据持久化
- 作品场景：游戏厅、足球场、钢琴地毯
- 晋段奖励：游戏厅数据核心

**段位作品：蛋仔游戏厅联机积分中心**

足球场和钢琴地毯作为联网终端上报比赛事件，游戏厅负责接收、去重、保存、查询积分并安全兑换奖励。

| 章节 | 目标 | 独立检查 |
|---|---|---|
| 找到客户端、服务端和端口 | 理解 IP、端口、连接和请求响应。 | 客户端退出后服务端仍能接受下一位客户端。 |
| 为比赛事件划清边界 | 设计长度前缀协议并处理部分读写。 | 将一条消息拆成多次发送仍能正确解析。 |
| 处理掉线与超时 | 区分正常关闭、连接重置、超时和可重试错误。 | 服务器中途断开时客户端明确结束或在上限内恢复。 |
| 同时接收多个终端 | 复用线程知识处理多个本地客户端。 | 一个客户端停发时其他两个仍可完成。 |
| 设计积分与兑换数据 | 学习表、主键、外键、唯一约束和查询。 | 重复 event_id 插入失败且余额不变化。 |
| 从 C++ 安全访问 SQLite | 使用预编译语句、绑定参数和 RAII。 | 正确保存并查询含空格、引号和中文的名字。 |
| 让积分与兑换一起成功或失败 | 用事务维护多表一致性。 | 兑换库存不足或中途失败时余额和兑换记录都不改变。 |
| 完成终端到数据库的全链路 | 联调 C 客户端、C 网关、C++ 服务和 SQLite。 | 终端重复提交、断线重连后最终只计一次积分。 |

**Boss：全岛联机积分赛** — 足球场与钢琴地毯同时上报，网络会分片和断线，客户端可能重复发送，数据库写入中途也会失败。

| 章节 | 目标 | 独立检查 |
|---|---|---|
| 确定作品使命与边界 | 从一个具体使用场景写出目标、约束和验收故事。 | 给出三个成功场景和三个失败场景。 |
| 画出自己的系统结构 | 决定组件、数据流、信任边界和技术选择。 | 解释为何每项技术解决当前问题而非只为凑数量。 |

| 让系统在真实故障后恢复 | 处理进程退出、断线、损坏输入、硬件异常或数据库忙。 | 进程中断后重启，已确认结果不重复、未确认结果可解释。 |
