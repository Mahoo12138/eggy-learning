## 实际浏览器验证

下列为本轮主任务在真实浏览器完成的操作核验，区别于 Node 测试：

- 维护题目后，历史答案保留旧题快照，当前任务显示新版本；训练保存后刷新仍存在。
- 新增单元可保存草稿，刷新后可读取；多标签页交错保存返回 412，未保存输入保留。
- 离线保存明确失败，输入保留；恢复连接后重试成功。
- 暂停周、续做和预览可使用；同任务下已完成自测与部分完成工作并存时，未完成工作仍续排，手填 60 分钟剩余估时保留，新恢复自测排在工作前。
- 切换单元加载缓慢或失败期间禁用编辑，保留旧表单，避免把输入写入另一个单元。
- 只读课程路线随课程变化更新，全屏可进入和退出。
- 管理页、路线与研究图表的浅深色主题可用；1440 和 390 像素宽度没有页级横向溢出。
- 最近四周原定、调整后和实际分钟数的条形对比在深色和窄屏下可读。
- 研究报告保留三张 ECharts SVG 图表；报告内部链接返回 200；以上检查未出现未处理的 `pageerror`。

## 双人分工验证

两个独立浏览器上下文连接同一份临时数据，完成以下联动操作；测试数据没有写入正式仓库：

- 管理者编辑带验收关联的思考题，学习者作答、保存证据与复盘，管理者在只读档案中查看。管理页 DOM 不包含训练、作答或验收保存表单，学习页 DOM 不包含课程编辑器。
- 管理者改题后，学习者旧页提交返回 412，输入保留；更新要求并明确核对新版后可提交，旧题和新题的答案快照同时可查。
- 更新要求时模拟单元请求失败，界面继续使用旧版本并保留输入，没有半更新或假成功；恢复后可读取新版。
- 管理者归档题目后，尚未保存的答案与证据经再次输入、切换页签、保存草稿和导出仍保留；明确处理旧题草稿后才允许提交当前正式记录。
- 双方预览同一周计划，先保存者成功，后保存者收到冲突且输入保留；切换页签和刷新保留核对结果、证据选择、剩余估时、自定义目标及零容量暂停。
- 远端替换周计划导致旧片段消失时，原核对输入留在可导出的本页备份，界面提示重新核对。
- 管理者可以显示归档单元并只读查看历史；学习者入口默认选择仍有效的单元。首次进入训练页即可关联已保存周计划，无需先访问周计划页。
- 学习者 Git 页仅展示学习 Author 提交，管理者 Git 页仅展示其余维护提交；分类使用临时 Git 仓库验证，不改变正式库身份或历史。
- 正式服务上的两个入口、全部页签、首页与课程/调研入口链接均已实际检查；1440 像素桌面及 390 像素手机宽度、深浅色显示正常，无未处理的页面异常或页级横向溢出。

正式 `data/curriculum.json` 和 `data/schedule.json` 的 SHA-256 在本轮前后一致，正式工作区仍无训练档案。拆分未增加账号、密码、依赖或第二套数据源。
