## 2026-10-18 恐龙蛋操作系统课程与完整代码交付验收

恐龙蛋现为 `version: 3` 的十二章完整课程，课程发布版本为 `publishedRevision: 11`。常规学习由 12 章 × 5 场组成，每章固定为“可观察现象 → 底层心智模型 → 三道服务端判定理解题 → 三次累计代码增量 → 本地运行手册 → 有界独立变式”，共 60 场；Boss“全岛闭园巡检总演练”分四阶段，典型总量为 64 场。晋段要求十二颗章节星，保留 `dinosaur-night-patrol-project`、`dinosaur-night-patrol-boss`、`trophy-night-patrol-lamp` 以及原有六个章节稳定编号。

课程从程序文件、进程、用户态、内核态、C 库、系统调用和 `errno` 开始，再依次覆盖文件描述符与短 I/O、文件系统状态与原子替换、虚拟内存与写时复制、`fork/exec`、`waitpid` 与僵尸、管道帧协议、`O_NONBLOCK + poll`、`sigaction + self-pipe`、单调 deadline 与进程组、`rlimit` 和最小继承、监督状态机与崩溃恢复。最终累计作品由 `patrold`、多个 `exec` 后的 `patrol-worker` 和独立 `patrolctl` 组成；管道、FIFO、信号桥和 deadline 进入同一个 `poll` 事件循环，追加式日志与原子快照负责重启对账。课程合同明确要求真实 PID、PGID、fd、退出状态、`strace`、`ps` 与 `/proc` 证据，单进程顺序函数或只打印相同文本不能作为作品验收。

本轮补齐了与课程同步的完整代码交付包：起始脚手架立即提供完整工程，36 个引导步骤对应 37 个可下载快照，最终快照包含 62 个文件。每一步都提供本步目标文件的完整内容，再要求学习者做范围明确、能观察结果的修改；当前步骤没有用省略号或隐藏缺口代替实现。学习页面可以下载起始工程、当前章节快照和最终源码 ZIP，也可以逐个文件复制。最终工程包含构建、单元测试、端到端测试与 Docker 验证入口。实际使用网页相同的 ZIP 生成模块打包最终代码包，产物含 70 个 ZIP 条目，解压后得到预期的 62 个文件；随后直接从解压目录执行 `./verify-docker.sh`，Alpine 测试与 smoke check 均通过。

最终工程已在 Alpine Linux Docker 环境完成 **15/15** 验证，包括 12 项单元测试和 3 项端到端测试；覆盖 `fork/exec/waitpid`、帧化管道、`poll`、self-pipe、单调 deadline、进程组 TERM/KILL、资源限制、追加日志、原子快照和 FIFO 控制。审计还发现并修复了父进程在非阻塞配置失败时可能遗留子进程的问题：失败路径现在先终止并回收尚未加入 worker 表的子进程，避免产生僵尸或失管进程。网页本身仍不会编译或自动评分 Linux 多进程工程；上述 15/15 来自代码包在 Linux Docker 中的实际执行，学习过程中的 `strace`、`ps` 与 `/proc` 证据仍需在原生 Linux、WSL2 或具备相应权限的 Linux 环境采集。

## 2026-10-18 STM32 完整课程与代码交付验收

鸵鸟蛋现为 `version: 4` 的十一章完整课程，目标芯片固定为 **STM32F103C8T6**。每章遵循“可观察现象 → 概念模型与术语 → 2 至 4 道理解题 → 三次完整代码增量 → 运行手册 → 独立变式”，总计 55 个常规学习场次；Boss“摩天轮闭园前安全演练”再用四阶段综合演练覆盖台架预检、时序与输入压力、传感与通信故障、复位与放行，典型总量为 59 场次。课程要求十一颗章节星，沿用“练习得经验、首次独立变式得星、Boss 晋段”的全局规则。

十一章依次覆盖复位与 `main`、GPIO 输出与安全灯、GPIO 输入与上下拉、按键消抖、非阻塞时间、定时器 PWM、中断与主循环、UART 诊断、ADC 量化与滤波、I²C 传感器与超时、故障锁存与看门狗。第一章只用构建日志、下载校验、断点、PC 地址和 Watch 变量证明固件运行；第二章从实体引脚、VDD/GND、电压与电流路径推出 GPIO 输出；第三章从高阻输入和悬空现象推出上下拉，再区分 raw 电平与 pressed 业务语义。普通上拉按钮无法只凭高电平区分“正常释放”和“断线”，课程明确保留这一诊断边界。GPIO 不直接驱动电机，输出限定为 LED、蜂鸣器或额定驱动器的逻辑控制输入。

本轮补齐了 STM32F103C8T6 对应的完整起始工程和最终源码：33 个引导步骤对应 34 个完整快照，基线与最终工程各包含 63 个文件；33 步中共有 37 项有实际行为意义的学习者修改。学习页面可以下载起始工程、章节快照和最终源码 ZIP，也可以复制单个文件。代码包包含 `FerrisControl.ioc`、主机模拟、目标端 HAL 适配、完整应用循环、接线和故障资料；`docs/cubemx-integration.md` 给出 CubeMX 生成文件与 15 个课程目标源文件的准确边界，以及 `main.c` 的 USER CODE 接入内容和中断入口检查，避免把主机 demo 或第二套 IRQHandler 加入目标工程。实际使用网页相同的 ZIP 生成模块打包最终代码包，产物含 71 个 ZIP 条目，解压后得到预期的 63 个文件；随后直接从解压目录执行 `./scripts/verify.sh`，12 项测试和集成 demo 均通过。

主机侧已完成严格 C17 编译下 **12/12** 测试和集成 demo；ASan/UBSan 配置也通过 **12/12** 测试及 demo，15 个目标源文件完成 Clang 静态分析。审计中修复了中断与主循环交换事件快照的临界区：代码现在保存进入临界区前的 PRIMASK，短暂关中断后恢复调用前状态，并分别覆盖“原本开中断”和“原本关中断”两种测试。中断适配文件只保留绑定与 HAL 回调，标准 `TIM2_IRQHandler`、`USART1_IRQHandler` 和 `SysTick_Handler` 继续由 CubeMX 生成文件唯一提供。

当前机器没有完成 STM32CubeMX/STM32CubeIDE 重新生成、ARM 交叉编译、ST-LINK 下载和 STM32F103C8T6 真机电气验证。因此，上述结论证明的是课程包、主机逻辑、HAL stub、目标源码边界和静态分析，不等同于固件已在真实开发板运行。首次上板仍需核对 `.ioc` 迁移结果、引脚冲突、目标构建、烧录、串口日志、复位原因和故障注入证据。
