# 作品源码交付维护

课程正文、完整快照和最终工程共同构成作品源码包。`courseware/` 中的源码、manifest、累积快照，以及 `data/project-code/` 中的发布包都属于交付内容，应提交到 Git；编译产物和运行数据库不属于交付内容。

## 发布 module

`lib/project-code-publisher.mjs` 集中维护源码发布的 interface：课程脚本提供一个作品的组装规则，module 负责身份、课程与镜像、代码合同、摘要、版本、运行锁和原子保存。

- `scripts/sync-ostrich-code-package.mjs` 与 `sync-dinosaur-code-package.mjs` 保留完整脚手架和课程实验的组装规则。
- `sync-peak-code-package.mjs` 与 `sync-super-code-package.mjs` 使用 manifest 组装累积快照；章节顺序和步骤编号必须与正文一致，不能通过覆盖编号掩盖错配。
- 四个脚本都支持 `--check`：读取并校验候选结果，不写数据、不取得写锁。只有超级凤凰蛋支持 `--with-draft`，用于同时采用正文草稿。
- 真正发布会取得与学习服务相同的运行锁，因此先停止学习服务；锁冲突会明确失败。发布前重新核对读取过的文件，拒绝覆盖期间发生的手动修改。
- 作品内容改变时增加课程版本。源码包缺失或损坏、但课程引用未变时可重建包；完全无变化时不改写文件或增加版本。
- 拒绝作品版本回退；候选课程必须能继续读取现有学习记录和周卡。两份记录只参与兼容性和冲突校验，发布不会改写它们来迁就新课程。
- 发布复用 `Store.writeDataBatch`，一起保存源码包、作品详情和课程索引。失败时保留可恢复的原版本；不要手工删除异常退出后留下的目录交换备份。

课程脚本仍负责教学选择，发布 module 不把两个课程的主题文案强制改为相同，也不把完整脚手架课程改造成从空目录起步的课程。这个 seam 的 depth 来自四个调用方不再分别承担发布顺序和一致性规则；删除它会让这些规则重新散落到脚本里。

```sh
node scripts/sync-ostrich-code-package.mjs --check
node scripts/sync-dinosaur-code-package.mjs --check
node scripts/sync-peak-code-package.mjs --check
node scripts/sync-super-code-package.mjs --check
```

修改巅峰或超级课件源码后，先运行相应 `courseware/*/generate.py`，再检查同步脚本的候选结果。需要发布时停止学习服务，去掉 `--check` 执行同步，运行 `node scripts/export-plan.mjs` 更新训练计划，最后重启服务。鸵鸟和恐龙脚本保留原有正文修正规则，因此源码摘要不变时，正文变化仍可能使课程版本增加。

## 读取 module

`lib/project-code-reader.mjs` 的 interface 仅包含 `readPublished(project)` 和 `validateCandidate(project)`。服务器启动、学习者读取和后台保存候选课程共用同一套文件与合同验证。

读取会限制文件字节数，确认普通文件，校验 SHA-256 和章节引用；读取期间文件变化会明确失败。缓存同时绑定课程合同与文件身份，文件替换或同长度改写后还原修改时间都不能沿用旧快照。返回的快照冻结，防止调用者改坏缓存。候选校验始终重读文件，不使用也不填充已发布缓存。

这使文件身份、完整性和缓存失效规则具有 locality。测试穿过与服务器相同的 interface，在真实临时目录制造坏文件、引用变化和文件替换；保留 HTTP 集成测试检查上下游组合行为。

## 验证

```sh
node --test tests/project-code-publisher.test.mjs tests/project-code-reader.test.mjs
node --test tests/*.test.mjs
```

发布测试验证临时目录中的四个真实命令、只读检查、无变化重试、活动进程锁、冲突与中途失败恢复。课程测试继续按每一步复制文件、构建并运行，确认汇集代码后能还原完整工程。浏览器竞态检查见 `scripts/verify-course-preview.mjs`，需独立环境已安装的 Playwright。
