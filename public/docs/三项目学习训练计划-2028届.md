# 三项目学习训练计划 · 2028 届

适用起点：南昌航空大学软件工程普通本科、大二、2028 年毕业；学过基础 C/C++，正在学数据结构，尚缺少 Linux、MCU 和完整项目经验。计划是训练建议，所有产出都表示要完成的目标，不表示候选人已经具备相应能力。

每周可投入四次、每次 2–3 小时。这里按 **32 个学习单元、约 256–384 小时**安排；按一周一个单元约 32 周。单元代表内容顺序，不是必须赶上的日历。考试、环境问题和未通过的验收可以顺延；已掌握者直接做本单元第 4 次独立验收，通过后跳过重复训练，不补虚构出勤。不要为了按期填满页面牺牲课程、休息或真实理解。

相比原来的 12 周体验计划，这次把“做什么、产生什么、怎么验收、失败后怎样追查”连在一起：先做 C / Windows TUI 的 whatforeating，再做 C++ / Linux 迷宫，最后做 MCU 反应力游戏盒。三个项目依次推进，不同时开工。第二个软件项目复用第一个的输入、状态和文件经验，重点转到容器、资源管理与游戏规则；MCU 项目再引入真实输入、时间和硬件约束。

## 1. 三个作品各负责什么

### whatforeating · 今天吃什么

依据用户确认及[已有项目讨论](https://chatgpt.com/share/6acc992f-0a74-83ec-9457-dd38265a747c)，已确定：**C 语言、Windows 开发、CLion、初版 TUI、不使用第三方 TUI 框架，随机对象是菜品。** 分享里的 C++ 是早期助手假设，不能作为本项目语言依据。

正式随机策略尚未确定。完全随机、简单权重、根据历史调整都不能被写成已确认需求。本计划采用基础随机选择作为学习基线；“换一个、确认结果、保存简单本地记录”是可调整的训练建议，并不冒称已经批准的完整产品功能。历史记录暂不参与推荐权重，也不擅自要求连续抽取绝不重复。

练习用 `rand()%n` 时应理解简单取模存在偏差，不宣称严格均匀；反复抽几十次只能帮助发现索引错误，不能证明公平。先把 0、1、满容量与重复操作处理正确，正式随机策略确定后再调整这一处函数。

只做一个清楚的文字界面：固定容量菜品表、选择与确认、少量本地记录、键盘操作与可靠退出。预置中文菜名可用；本轮不要求中文编辑器、通用终端控件库、复杂对齐、数据库、账号或云同步。学习证据重点是 C 数据与输入边界、文件失败、控制台模式、中文输出、窗口变化和退出恢复。

### 终端迷宫探险

在完成第一个 C 项目后进入 **C++ / Linux**。固定小地图、移动碰墙、一把钥匙和一扇门、找到出口、文本存档继续探险，足够形成可给同学试玩的小作品。

重点是用 `string`、`vector`、结构体和小函数表达状态，理解作用域与资源管理；不照搬平台 TUI，也不因为换 C++ 就造继承体系。保留普通回合制文本输入输出，暂不做图形引擎、实时动画、联网、随机地图生成或 AI NPC。存档比第一项目复杂，适合练习“读入临时状态、完整校验、再一次应用”，以及错误发生后当前游戏保持不变。

### 桌面反应力游戏盒

使用一块学校或已有的、具备 LED、按钮及可用串口条件的板。等信号亮起后按键，识别抢跑与超时；一局五轮，串口展示有效反应成绩。趣味来自短反馈和与朋友比较，不靠增加很多器件。

从对应板的基础示例入手，型号、供电、引脚、电平和串口参数均依实际资料确认，不照搬另一块板的配置。按钮消抖、非阻塞等待、状态机、时间差、UART 与混合操作是主线；显示屏、RTOS、联网排行榜、电机和模型部署留到之后真正有需求时。这个游戏未经仪器标定，不能当作竞技级精密计时器。

没有硬件时可先验证纯逻辑或仿真，但烧录、真实输入、电气行为与串口结论都保留待验证，不能因仿真通过就勾选真机验收。也不需要为了追赶日期临时购买整套设备。

## 2. 怎样执行与留证据

每个单元有一个目标、前置条件、一项可交付产出、三条验收标准和四次训练。每次训练均给三步具体操作、预期产出和结束检查。前 2 小时可按 20 分钟阅读、70 分钟动手、20 分钟检查、10 分钟记录安排；有第 3 小时用于复习或整理，不增加下一阶段必做内容。安装、查资料、连接硬件和定位环境问题都算实际训练时间。

建议照下面这一条链记录，避免把“写过日志”当成“已掌握”：

**本单元目标 → 本次任务 → 实际尝试 → 证据 → 验收或卡点 → 下一次行动 → 复测。**

- 开始前：选择单元，必要时填目标日期和本次调整；读清结束标准，再写代码。
- 结束时：记录实际日期、分钟、做了什么与结果。证据可以是源码版本、文件位置、输入输出、截图、串口原始记录或测试表，不要求每次都录视频。
- 卡住时：记录最小复现、预期与实际、已排查内容，再写一个可执行的下一步。下一次对同一任务追加复测记录，保留第一次失败，不用重写叙述把它抹掉。
- 通过时：必须有本次结果与证据，AI 提供代码时还要写清独立检查。第 4 次独立验收通过，并逐项检查本单元三条标准后，再确认单元完成。
- 复盘时：只回答一个学会的机制、一个仍不懂的点、下一次最小动作。若复测发现回退，记录真实失败，重新进入修复，不继续声称已经稳定。

记录写够用即可，不建设额外知识库、积分、打卡排名或标签体系。学习时长说明投入，不证明能力；录入记录条数也不是掌握程度。连续两次卡在同一处，就缩小程序或带着复现证据向同学、老师或 AI 求助。所有日期留给实际安排，不自动生成过去的学习经历。

可用的简短故障记录示例：

> 任务：迷宫加载存档。预期：坏存档被拒绝且当前位置不变。实际：位置已改变、门状态未更新。复现：加载缺最后一行的文件。根因：读取过程中直接修改了当前状态。修复：先读入临时结构，检查完整后应用。复测：缺行、越界、正常文件交错加载均符合预期。证据：源码版本和三次运行记录。

这个例子是格式示范，不是已经发生的候选人经历。

## 3. AI 怎么用，才能留下自己的能力

AI 可以用来解释一个概念、阅读报错、提出下一步观察、补充测试边界或评审一小段代码。提问时带上最小代码、预期、实际和已试过的操作，先要求提示与原因，不一开始要求生成整套项目。

若采用 AI 代码，记录采用了哪一段、自己改了什么、怎样验证；尤其核对输入长度、资源关闭、Windows API 返回值、时间单位和真实板引脚。AI 给出的貌似完整代码不替代真实构建、测试或硬件说明。

每单元第 4 次验收以及第 30–31 单元隔周复测，前半段先独立完成核心操作和小修改。可以查语言/API 文档，不让生成式 AI 提供主体实现；卡住后可以求提示，但本次记录应保留帮助范围，待下一次能独立完成时再通过验收。

这些训练不会因为 AI 能生成代码而失去意义：目标是把需求变成规则，识别错误、选择证据、维护已有状态，并在陌生小修改后知道怎样检查。是否掌握，以能解释、能修改、能定位和复测为准，不以手写了多少行或用了多少新框架为准。

## 6. 每单元四次训练

下面内容与 `study-curriculum.json` 对应，供离线阅读；实际日期、尝试记录与验收状态在“学习计划与进度”页面管理。

### 单元 01 · 起点验收与输入边界

**目标：**确认自己真正会的部分，修复输入、循环和数组的基础缺口。

**先具备：**已有能编译运行 C 的环境，可沿用 Windows / CLion，不同时安装 Linux。

**本次概念：**数组边界、循环与条件、输入校验。

**交付产出：**一个接收最多 10 个整数的小程序及输入—预期—实际结果表。

#### 第 1 次 · 先验收，再决定补什么

1. 用 C 接收 5 个分数并求最大值与平均值。
2. 试全 0、全 100、混合值和一个字母输入。
3. 记录不会的点；已能完成者直接做本单元第 4 次验收。

**留下：**起点程序和真实缺口清单；通过者不重复四次出勤。

**结束检查：**混合值先手算，程序结果一致；能解释循环访问的下标。

#### 第 2 次 · 补数组和函数

1. 将数量改为 0–10，由用户先输入。
2. 把最大值、平均值分别放入函数。
3. 约定 0 项时输出“没有数据”，不计算平均。

**留下：**接收可变数量的统计程序。

**结束检查：**0、1、10 项各运行一次，无非法下标。

#### 第 3 次 · 让错误输入停在边界

1. 检查数量是否成功读入并位于范围内。
2. 逐项检查成绩是否为 0–100 的整数。
3. 对字母、负数、超上限分别记录预期再运行。

**留下：**至少 6 行输入用例表。

**结束检查：**错误输入后明确退出；未输出看似有效的平均值。

#### 第 4 次 · 独立验收：改一个规则

1. 先不用 AI 写“统计大于指定值的数量”。
2. 用全相等、阈值两侧、0 项三个用例检查。
3. 口述数组边界和一个修复过的错误并保存证据。

**留下：**独立修改的代码版本与验收记录。

**结束检查：**能重新运行并解释结果；不通过就补对应缺口。

**单元验收：**

- [ ] 0、1、10 项输入均按约定处理，超过容量不会越界。
- [ ] 字母、负数量和超范围数值有明确提示，不继续生成伪结果。
- [ ] 不靠生成代码独立增加“统计大于指定值的数量”，并解释边界。

**常见失败：**

- 先求平均后检查数量，导致除零。
- 输入失败后仍使用未得到的新值。

### 单元 02 · 坐标、函数与小状态

**目标：**把语法转成可描述的程序规则，为地图与设备状态做准备。

**先具备：**已能处理单个合法输入，并避免数组越界。

**本次概念：**结构体、函数输入输出、状态与规则。

**交付产出：**一个在 5×5 空场地上移动坐标的小程序和状态表。

#### 第 1 次 · 先在纸上移动

1. 画 5×5 格子，约定行列从 0 开始。
2. 列出上下左右对坐标的改变。
3. 定义含行列的结构体，输出起点。

**留下：**坐标约定和一个位置结构体。

**结束检查：**从中间连走上、右、下、左应回到起点。

#### 第 2 次 · 让一条命令变成一次移动

1. 用字符命令代表四个方向与退出。
2. 写函数计算候选位置，再检查是否在场地内。
3. 只有合法时才将候选位置写回当前状态。

**留下：**带移动函数的坐标程序。

**结束检查：**撞四条边都保持原位，正常移动只变化一个坐标。

#### 第 3 次 · 把输入与规则分开查错

1. 把读命令、算位置、显示位置分成小函数。
2. 连续输入未知字符和合法命令。
3. 用临时输出核对更新前、候选和更新后位置。

**留下：**一条可复现错误的观察记录。

**结束检查：**未知命令不移动；退出后不再读下一条。

#### 第 4 次 · 独立验收：加一格障碍

1. 自行指定一格障碍，先写进入时预期。
2. 不看现成答案修改合法性判断。

### 单元 24 · 测出一次反应时间

1. 设计一行一个结果的短文本格式。
2. 仅在本轮结束和本局结束输出。
3. 加上轮次、结果类型、有效反应值与汇总。

**留下：**一局串口成绩单样例。

**结束检查：**无效结果明确写抢跑或超时，不伪造数值。

#### 第 3 次 · 查一次连接或配置故障

1. 在终端侧改错波特率，观察并恢复。
2. 游戏中断开终端再重新打开。
3. 确认日志输出没有放在影响计时的高频循环里。

**留下：**一次串口故障与恢复记录。

**结束检查：**终端未打开时游戏仍执行，恢复后能获取后续完整记录。

#### 第 4 次 · 独立验收：复现一局成绩

1. 重新连接串口并独立配置参数。
2. 玩完整一局，保存原始终端文本。
3. 依据文本解释每轮状态与汇总计算。

**留下：**可核对的五轮原始日志。

**结束检查：**原始记录支持结论；尚无真串口时注明模拟输出并待补。

**单元验收：**

- [ ] 正常、抢跑、超时记录字段一致且可辨认。

### 单元 27 · 混合操作与计时边界

**目标：**主动寻找偶发重复触发和状态污染，冻结核心功能。

3. 保留每次异常的原始串口输出与操作步骤。

**留下：**混合操作回归结果及失败证据。

**结束检查：**出现异常后还能定位到具体轮次与状态。

#### 第 3 次 · 模拟计数边界并修复

1. 查清实际时间计数的无符号类型和范围。
2. 用短小纯逻辑例子模拟起点靠近上限、当前值已回绕。
3. 采用可解释的时间差判断并复测普通时间。

**留下：**计数边界例子、预期值和修复说明。

**结束检查：**仅在约定短时跨度内解释时间差，不拿真实长等代替测试。

#### 第 4 次 · 独立验收：状态中途复位

1. 在准备、亮灯、结果状态分别复位。
2. 重玩一局并核对初始与最终记录。
3. 解释最难定位的一次问题及回归范围。

**留下：**候选固件和完整稳定性清单。

**结束检查：**故障未复现不等于已修复；仍有问题则留在本单元。

**单元验收：**

- [ ] 连续至少 3 局交错正常、抢跑、超时后，轮数与成绩仍正确。
- [ ] 等待、亮灯、结果三种状态复位后都回到约定初始状态。
- [ ] 用模拟时间值检查计数跨边界时的时间差，不需要真等计数器耗尽。

**常见失败：**

- 偶发错一次就直接增大延时，没有保留复现序列。
- 使用“当前时间大于开始时间加超时”的写法却不理解计数范围。
