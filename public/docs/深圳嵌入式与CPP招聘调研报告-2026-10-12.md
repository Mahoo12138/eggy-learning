## 1. 先确定学习目标

目前最有价值的目标是：**到下一轮实习准备阶段，能独立完成一个范围有限的 C/C++ 模块，解释其工作原理，定位真实错误，并用测试和测量证明修改有效。** 先补已有基础，再依次完成三个范围有限的个人项目：**C TUI 的 whatforeating、C++ / Linux 终端迷宫、MCU 反应力游戏盒**。三个项目提供不同环境的实践体验；完成后再依据兴趣、证据和目标 JD 选择一条长期主线，不同时推进三个项目。

AI 让获取示例、生成代码初稿和查询知识更方便。学习的成果可以转为四种可观察的能力：

1. **说清问题。** 输入是什么，输出是什么，哪些资源有限，出错时应怎样处理。
2. **看懂实现。** 数据存在哪里、谁负责释放、任务怎样协作、外设或网络怎样通信。
3. **验证结果。** 找到错误输入、异常顺序、超时或断连，判断程序是否仍符合约定。
4. **完成修改。** 改一个需求后，能找到受影响的地方，修复问题并检查回归。

最直接的新证据是云松鼠的 Linux 实习：它把使用 Codex/Claude Code，与理解、调试、验证生成代码同时写入要求。**基础知识的作用，是帮助你知道 AI 写出的程序什么时候可信、哪里有问题、如何改对。**[云松鼠 JD26](https://www.zhipin.com/job_detail/0e7a015daf46b9fb0nx629y8FFtY.html)

其他招聘依据包括：其域的实习包含单测、交叉编译与真机联调；影石要求 C/C++、算法、数据结构和多线程；艾讯的 1–3 年岗位要求独立定位卡顿、内存和业务流程问题；博彦要求维护线上游戏服务。这些任务都需要理解与判断。[其域 JD03](https://www.zhipin.com/job_detail/ff97d795e7b4ca3d0nN809W1FVtW.html)、[影石 JD01](https://www.zhipin.com/job_detail/c81c3593e859e3f10nd82Ni1E1NS.html)、[艾讯 JD08](https://www.zhipin.com/job_detail/3d42b583f734d1500nZ_2Nm0GFRY.html)、[博彦 JD09](https://www.zhipin.com/job_detail/70fdd743466b06e30nN60tu9EFNW.html)

这不能证明任何技能永远不变或保证岗位增长。它足以支持一个可执行选择：**先训练能够跨项目使用的理解、实现和排错能力，再按实际岗位增加专项技术。** 不需要先找出一种“永远不会被 AI 替代的语言”才能开始学习。

### 本阶段的投入顺序

| 优先级 | 内容 | 学到哪里先停 |
|---|---|---|
| **先建立共同基础** | 先复用课程中的函数、数组、结构体和基本数据结构；练编译、查错和说明。随后补内存、Git、读文档与测试。 | 能独立实现并修正一个小模块，能解释边界和测试；随后进入方向项目，不用等“学完全部语言”。 |
| **依次完成三个小项目，再定主线** | C TUI → C++ / Linux 终端迷宫 → MCU 反应力游戏盒。 | 每个项目固定范围，完成正常、异常和独立修改验收；之后选择 MCU、Linux 设备 C++ 或 C++ 后台深入。 |
| **从开始就使用 AI，但保留独立考核** | 用 AI 解释、提问、比较方案、辅助写测试；本人负责验收。 | 对采纳的代码能解释并改动；每单元完成一次无生成式 AI 的小修改。 |
| **遇到目标需求再学** | Qt/OpenCV、CAN、Bootloader/OTA、数据库索引、容器、端侧推理等。 | 做到目标模块需要的深度，不同时铺开所有技术。 |
| **当前可以暂缓** | 大模型训练、CUDA、自研完整 OS/数据库、复杂无锁结构、多个芯片/RTOS/框架同时学习。 | 某个明确目标岗位和已完成的基础项目提出需要时再启动。飞轮内核岗属于专项进阶例外。 |

“暂缓”是当前时间分配，不是断言技术没有价值。C++ 后台与设备应用要较早学习现代 C++；以 MCU 为主时，可先把 C、外设和调试练扎实。

样本是按方向、阶段和企业类型有目的选取，**不是深圳市场的随机调查**。增加数量改善案例覆盖，不能消除搜索、关键词、页面可访问性和人工筛选偏差；初轮部分后台列表还有薪资过滤。不能推算全市岗位占比、录用概率、市场薪资或AI普及率，也不能只按出现次数安排学习。26条不计记录包含关闭、明确门槛、专业或范围待核、正文不足、截止/待遇冲突以及同企业备选，并非26条都判定候选人不合格。详细规则和逐条排除理由见 [技术栈统计口径](技术栈统计口径.md)。

- **任职要求**：反映该岗位希望候选人已有的能力。
- **职责**：反映入职后要做什么，可用于设计练习，但不自动等于入职前必须全部熟练。
- **优先项**：基础满足后再增加，不能把所有加分项变成共同必修。
- **训练验收**：下文人为设计的练习标准，用于检查进步，不冒充招聘方考试。

学校明确要求 985/211、重点高校的量化岗位，不作为这位候选人的核心训练门槛。未明示学校限制的影石、飞轮等不能仅因普通本科就排除；飞轮的内核要求仍须作为高难度专项看待。

### 2.4 完成基础训练后，向实习推进的三条方向

**这是在基础与三个小项目之外，按目标方向逐步补齐的范围。** 线程、Socket、SQL、RTOS等按所选主线和项目需要依次加入，不是当前同时开学的任务。

| 方向 | 主线阶段逐步建立的能力 | 实习项目中练到的程度 | 1–3 年阶段再向哪里加深 | 暂缓/按业务选择 | 证据 |
|---|---|---|---|---|---|
| **MCU / 单片机** | C；一种 MCU；GPIO/定时器/中断；UART、I2C/SPI的常见使用；读基础电路和芯片手册；基本仪器调试。 | 驱动一个外设，采集数据并可靠传出；解释中断与主循环/任务的数据交接；有时间和内存记录。目标校招再补一种 RTOS 的任务、队列和同步。 | 实时性和资源取舍；软硬件联调；通信故障与售后问题；按产品学习升级、低功耗及量产支持。 | 多种MCU同时学、复杂PCB、所有工业协议、RTOS内核重写。 | JD07、JD14；JD13校招技能参照；JD02仅技术参照。 |
| **嵌入式 Linux / C++ 设备应用** | 现代 C++（对象、RAII、STL、生命周期）；Linux命令/进程/文件；构建调试；基本线程与接口。 | C++应用读设备或模拟输入；分模块处理、写测试，能构建部署、记录日志并恢复断连；真机能力须用真机验证。 | 线程与资源诊断；模块接口/状态机；性能；目标需要时补Qt事件循环、OpenCV、交叉编译/板端部署。 | 一开始同时学BSP/内核驱动、Qt、视觉、ROS、NPU全栈；这些不是一个岗位层次。 | JD03、JD01、JD05；JD08为1–3年设备应用样本。 |
| **C++ 后台 / 服务端** | 现代C++；OS/进程线程；TCP基础与socket使用；数据结构；数据库/SQL基础；构建、调试、日志。 | 一个有清楚协议和错误返回的服务；理解消息边界、断连、超时和线程同步；能复现并定位问题。 | 线上故障、性能和业务模块；过载、持久化恢复；按方向深挖游戏同步、音视频或存储。 | 起步就做大型分布式系统、K8s、自研数据库和无锁框架；先用简单模型获得可测基线。 | JD09；JD12是接受C++的Go方向；JD06为内核专项。 |

**基础训练之后，现代 C++ 的进阶范围：**引用与 `const`、类和对象生命周期、RAII、常见 STL 容器、智能指针、lambda；基础线程/互斥等到项目需要并发时加入。先能解释所有权和并发边界；复杂模板元编程、全套标准特性和手写 STL 不作为开工前提。依据 JD01/03/08；具体取舍是训练建议。

**MCU 的停止条件：**先在一个平台上完成“查手册—配置—读写—测量—排错”的完整过程。微雪要求多平台是1–3年样本，不意味着大二必须同时买多块板；usmile要求一种MCU与RTOS，可作为后续校招能力目标。

**飞轮的特殊性：**内存池、零拷贝、epoll、CAS、B+树/LSM在该内核实习JD中确实要求较深。先完成系统基础与普通服务，再决定是否走这一专项；不能把它们全部提前列为每个C++实习生的入门作业。

候选人已有基础 C/C++、正在学习数据结构，但尚未做能力实测。执行方案先保留 C 基础验收，再用三个有明确玩法和交付边界的项目积累经验。**它们依次推进，不要求同时掌握三个技术方向，也不把完成项目等同于达到实习门槛。**

| **① whatforeating 今天吃什么 / 5–12** | C + TUI：固定菜品表、基础随机练习、候选“换一个 / 确认”、本地结果文件和终端交互。 | C 数据建模、字符串与数组边界、模块划分、终端交互、文件与错误处理。 | Windows / CLion，不用第三方 TUI 框架；随机对象是菜品。正式随机策略未定，基础随机仅作为训练；不做交互编辑菜品、条件筛选或历史降权。 |

完成三个项目后再比较：是否更愿意追查程序数据与系统状态，还是读手册、看引脚和实际信号；是否能持续获得开发板；哪一个项目能独立解释、修改和复测。选择 Linux/C++ 后，再在设备应用与后台中定一个目标。暂时感到困难不能单独证明“不适合”，应区分基础缺口、工具环境与兴趣。

## 4. 从现在到 2028 年毕业：按成果推进

以2028年毕业为目标，具体毕业月份、课表和实习许可尚未知。新方案共有 **32 个训练单元 × 每单元 4 次 × 每次 2–3 小时 = 256–384 小时**。每周推进一个单元时约32周，假期、考试与环境准备可顺延；单元编号表示学习顺序，不是自动计算的日历截止日期。

| 时间窗口 | 训练重点 | 交付与阶段检查 | 招聘准备 |
|---|---|---|---|
| **从当前起，单元 1–4** | C 基础验收与补缺，复用数据结构课程。 | 能解释输入、数组边界、指针修改和固定容量记录；已会内容保留独立验收证据。 | 用 JD 校准长期方向，不需先学完所有技术。 |
| **接续单元 5–28** | 每次只推进一个项目：whatforeating → 终端迷宫 → 反应力游戏盒。 | 每项目有正常、边界、失败用例，以及至少一次独立变式；真机与模拟分开。 | 项目成果可逐步转入简历，但不虚构团队、用户规模和工程难度。 |
| **接续单元 29–32** | 缓冲、重做、延后复测和作品交付。 | 别人按说明复现；自己能解释一次完整故障与修改影响；保留未完成项。 | 选择一条主线，再检查当时接受2028届的实习条件。 |
| **2027年可实习时段** | 有合适机会时参与真实团队；没有时做有使用者或评审者的校内/开源项目。 | 留下个人负责模块、评审反馈、修复和回归记录；如实区分课程、个人、开源与企业经历。 | 单独核对出勤和月数。当前若干实习要求5天/周、5–6个月，不能假设适配一个暑假。 |
| **2027年下半年至2028年毕业前** | 结合真实校招补主线短板，围绕作品进行解释、调试和限时修改。 | 能说明个人贡献、资源/性能取舍与一个失败案例；重新抽样职位修订专项。 | 将2027年下半年作为关注2028届校招的计划窗口；实际开放时间和毕业窗口以企业公告为准。 |

### 学习时间怎么安排

按已确认的 **每周4次、每次2–3小时**安排，一个单元通常占8–12小时。前2小时用于主任务，第3小时优先用于未完成实验、查错和复盘，不自动加新框架。准备环境、阅读和整理证据均计入这段时间。

| 每单元四次 | 2小时基本安排 | 有第3小时如何使用 |
|---|---|---|
| 第1次：理解与预期 | 对照资料运行最小例子，写本单元输入、输出和失败规则。 | 补课程薄弱点，画数据或状态变化。 |
| 第2次：实现 | 自己实现一个小功能，保存可回退的代码版本。 | 换输入或拆分难点，避免抄完即结束。 |
| 第3次：查错与证据 | 先写边界/错误输入的预期，运行后定位、修复并回归。 | 复查同类问题，补测量条件和证据说明。 |
| 第4次：独立验收 | 用45–60分钟独立修改或重做，再核对验收和下一步。 | 复盘未掌握的一点，安排延后复测。 |

已有数据结构课程可以计入对应训练，不额外叠一套完整题库。考试周缩小或顺延任务。**课外每周8–12小时，不等于实习每周能到岗4天**；后者通常按完整工作日计算，须另核实。

## 5. 执行计划与学习追溯

### 5.1 从一次独立验收开始

第一节沿用现有环境，允许查语法、用编译器和调试器，先不用生成式 AI 直接给完整实现：

1. 输入固定5个成绩，计算最大值和平均值；解释超范围、含字母或没有输入时怎样处理。
2. 用结构体保存“编号＋成绩”，最多10条；实现添加和查询，说明重复编号、查不到、记录满的行为。
3. 改一个小需求，解释数组边界、每个函数的输入输出与修改影响。

已有能力用实际结果确认，不必重刷所有语法。不会的部分拆成补练；不要因为“学过 C++”就默认掌握，也不把验收当成淘汰测试。节省的时间留给项目调试、复测或休息。

### 5.2 32 个单元的总安排

| 单元 | 阶段 | 交付关口 |
|---|---|---|
| **1–4** | C 基础验收与补缺：输入、函数、数组、指针、字符串、结构体与固定容量记录及查错。 | 能独立修改简单记录程序，解释边界与错误处理；保存一份完整故障记录。 |
| **5–12** | whatforeating：固定菜品表 → 基础随机练习 → 换一个与确认 → 本地结果文件 → Windows TUI、异常和交付。 | 结果来自有效菜品表；候选与确认状态、文件失败和退出行为明确；训练策略能解释，正式策略保留待定。 |
| **13–20** | C++ / Linux 终端迷宫：语言桥接 → 地图和状态 → 移动碰撞 → 存档恢复 → Linux 构建调试。 | 状态变化、越界与坏存档有检查；能解释对象生命周期，完成独立规则变更。 |
| **21–28** | MCU 反应力游戏盒：板与 GPIO → 状态机 → 非阻塞计时 → 消抖 → 反应时间和串口 → 真机验证。 | 提前按、长按、超时、连续多局与复位都有预期；记录测量限制和硬件条件。 |
| **29–32** | 重做、延后复测、缓冲与三个作品交付。 | 按说明复现，独立完成变式，整理未解决问题；选择下一阶段的一条主线。 |

逐单元的四次训练、知识点、产物与验收见 [三项目学习训练计划](三项目学习训练计划-2028届.md)。实际排期、日志和复测记录在 [学习计划与进度](../learner.html) 中管理。本调研 HTML 只总览路线、技能依据与训练建议，不统计个人进度。

### 5.3 追溯的最小闭环

**任务 → 实际记录 → 证据 → 验收 → 延后复测。** 完成按钮只是记录入口，投入时长和做过一遍都不能单独说明已经掌握。

| 记录层次 | 最少留下什么 | 为什么要留 |
|---|---|---|
| 任务与计划 | 所属单元、这次目标、计划日期；卡住时调整下一次范围。 | 知道当前在解决哪个具体问题，避免不断加课程。 |
| 实际训练 | 日期、用时、实际结果、卡点、下一步、AI使用及核验。 | 区分缺概念、缺练习和环境问题，也区分辅助完成与独立完成。 |
| 可复现证据 | 代码版本或文件位置、输入/操作、预期/实际结果；硬件任务补板型和测量条件。 | 以后能找回那次结果，避免只有一句“已完成”。 |
| 验收结论 | 条件是否满足、哪些没通过、下一次补什么。 | 一次未通过只补对应缺口，保留真实问题。 |
| 延后复测 | 隔一段时间独立重做或改一个变式，追加记录并关联上次结果。 | 检查离开教程后能否解释、修改和排错。 |

不需要给每次训练写长报告。普通训练用几句事实加一处证据即可；重要故障再写完整的“输入/操作 → 现象 → 根因 → 修复 → 回归”。每单元第4次训练完成独立验收，并逐项核对该单元的三个验收条件。AI 给过完整实现的部分，先记为辅助完成，之后用不同变式独立验收。

### 5.4 三个项目交付后，按目标方向深化

下表属于后续范围，不并入32个单元的默认任务。入门项目通过验收后，可以按当时能力和出勤条件尝试适配实习；不需要先完成表内所有专项。

| 主线 | 后续依次增加 | 有价值的成果 | 再按岗位选择 |
|---|---|---|---|
| MCU | 同一块板的一种UART/I2C/SPI外设 → 数据采集与测量 → 有明确多任务需要时再学RTOS队列/同步。 | 能解释接线、配置、时序和通信错误；处理读失败与超时，保留真机记录。 | OTA、复杂电机控制、低功耗、第二平台、端侧模型。 |
| Linux设备C++ | 一个设备或数据输入模块 → 错误处理与日志 → 按需要加入线程、交叉编译和目标板。 | 可复现构建，处理输入错误与设备断开；主机模拟与真机验证分别注明。 | Qt、OpenCV、ROS、BSP/驱动、NPU部署。 |
| C++后台 | TCP/Socket与消息边界 → 单个小服务 → 持久化/SQL → 有明确需求时再加并发。 | 能重现半条消息、断连、超时和重启问题；有测试、日志和测量条件。 | 分布式、K8s、数据库内核、无锁优化；内核专项另行投入。 |

## 6. AI 应怎样进入训练

### 6.1 招聘里的 AI 信号要分清含义和强度

| 类型 | 真实证据 | 对大二训练的含义 |
|---|---|---|
| **用AI辅助开发并核验** | 云松鼠JD26明确Codex/Claude Code与理解、调试、验证；usmile JD13写编码/调试/研究；博彦JD09写使用AI工具；爱玩JD23列工具品牌；新增天贝JD32写愿意借AI提升编码效率和质量。 | 从小程序开始练“给约束—读输出—运行—反例—解释”。JD13/JD32为2027届，JD23为2025/26届，仅技能参照；“愿意使用”不等于“熟练掌握”，工具品牌也不是统一考试范围。 |
| **把AI功能集成进产品** | 湾测JD04偏算法部署；OPPO官方系统岗单列AI原理/API、算法复现与功能落地，并说明不涉及模型训练。 | 基础项目稳定后按目标补集成与测量。两者都是2027届参照，不前移成当前MCU新手共同门槛。 |
| **开发AI相关平台/基础设施** | 元芯JD05做体系结构/平台调试并提供培训；飞轮JD06做检索内核；追一JD12做AI产品组件。 | 有系统基础可以选择AI相关业务；公司业务有AI不等于候选人必须训练大模型。 |
| **把AI框架知识列为加分** | 新增极限网络JD45把了解AI框架/算法/应用列为优先，示例有TensorFlow/Keras/PyTorch等。 | 这是信息安全后台的加分方向，不算AI辅助编程或明确的产品集成职责；不据此让所有后台初学者增加整套模型训练课程。 |

本次50条样本中，**5条在任职条件提及AI辅助开发**（JD09/JD13/JD23/JD26/JD32），强度从愿意使用到熟练使用、理解和验证不等。另有2条明确AI产品/算法集成职责（JD04/JD12）。这两类分别统计；官方OPPO参照和JD45的AI框架加分没有并入上述计数。它们支持练习工具使用与验收，不能证明所有深圳岗位都要求同一AI工具，也不要求现在同时学习多套模型框架。

### 6.2 每次练习使用同一套流程

1. **本人先写任务说明。** 输入输出、资源或时间约束、失败时的行为、至少一个反例。不会写清楚的地方先提问。
2. **先做一次有目的的尝试。** 建议用15–25分钟尝试、复现或查资料，再向AI提出具体卡点；完全不认识的概念可以直接让AI讲解，不需要长时间盲猜。
3. **分级获取帮助。** 先要提示和反问，再要局部示例或最小改动。若用了完整实现，把该次记录为“辅助完成”，之后用不同变体独立复做。
4. **本人核对并运行。** 检查接口与版本、数据长度与所有权、任务/线程边界；运行原测试及至少一个反例。硬件相关结论回到手册和实际测量。
5. **本人解释与修改。** 能说明为什么有效、什么时候失效；在每单元第4次训练中用45–60分钟独立考核，可查文档、用调试器与测试，暂不调用生成式AI给实现。

学习新概念时，适当保留自行推导和实现的空间；已经理解的机械性代码、构建脚本或文档初稿可以更多交给AI。调整依据是独立考核和排错表现，不以“手写比例”评判学习好坏。

### 6.3 用这四个指标替代“AI写得比我快”的比较

| 指标 | 每两周记录什么 |
|---|---|
| **独立理解** | 能否不依赖助手解释本模块的数据流、资源和失败行为。 |
| **陌生变更** | 换一个输入约束或需求，能否完成修改并发现影响。 |
| **故障定位** | 本期独立定位了哪个以前不会的问题；根因证据是什么。 |
| **可复现交付** | 别人能否按步骤运行；测试和测量是否能重做。 |

某项仍离不开提示，就针对该项安排下一次小练习。学过的概念能帮助更快发现AI给出的错误、选择更简单方案或解释真实故障，就是已经发生的学习收益；不必等到做出比工具更大的程序才承认进步。

### 6.4 学习资料只在遇到对应问题时使用

先沿用自己的课程、教材和已能运行的编译环境。下列5项是免费公开的一手补充资料，**不要求同时开学，更不要求先全部学完**；硬件、正式学分、教材付费版本等不包含在“免费”承诺内。

| 什么时候用 | 资料 | 本轮只取什么 |

| C数组、结构体、指针不稳时 | [GNU C入门与参考](https://www.gnu.org/software/c-intro-and-ref/manual/html_node/index.html) | 查当前概念与小例子；含GNU扩展，不能默认任何MCU编译器都支持。先不把整本当零基础课程。 |
| 单元13–20：C++迷宫 | [Stanford CS106L 2026春季归档](https://web.stanford.edu/class/archive/cs/cs106l/cs106l.1266/) | 先引用、容器和对象生命周期，之后补RAII；暂缓高级模板和追最新标准。 |

## 7. 未来五年哪些变化值得跟踪

下面是**条件性推断**，不是岗位数量、薪资或替代率预测。对这位候选人，2026–2028是准备期，2028–2031大致对应毕业后前三年。

| 方向判断 | 依据与限制 | 对学习安排的影响 |
|---|---|---|
| AI辅助开发可能更多进入团队流程。 | 本次多条深圳JD已明确提及，尤其JD26把工具使用和人工验证并列；全球开发者调查支持工具采用信号，但不代表深圳比例；METR研究也不能给出通用提效倍率。 | 训练工具使用与核验；基础能力和独立修改仍作为考核对象。 |
| 部分MCU/终端产品会增加端侧推理。 | STM32N6、CMSIS-NN、ESP-DL提供技术路径；实际需求取决于产品、成本和收益。 | 先做可靠采集/通信/控制，再按需要加量化与部署；普通控制岗位不必先学完整AI栈。 |
| Linux/C++与AI部署的交叉值得关注。 | ONNX Runtime等有实际线程与资源约束；深圳政策支持终端和工业软件，但政策不证明净增岗位。 | 生命周期、并发、性能测量与设备集成可以复用；模型/框架专项等目标出现再加。 |
| 维护和验证的要求可能随产品复杂度提高。 | 当前JD已有测试/现场/线上问题，C++指南和RTOS长期维护资料也强调工程约束。 | 让主项目经历重启、故障、版本修改和回归；从“完成初版”走向“持续可维护”。 |

依据：[Stack Overflow 2025](https://survey.stackoverflow.co/2025/ai/)、[METR 2026更新](https://metr.org/blog/2026-02-24-uplift-update/)、[STM32N6](https://blog.st.com/stm32n6/)、[CMSIS-NN](https://arm-software.github.io/CMSIS-NN/v7.0.0/index.html)、[ESP-DL](https://docs.espressif.com/projects/esp-dl/en/latest/tutorials/how_to_run_model.html)、[ONNX Runtime](https://onnxruntime.ai/docs/performance/tune-performance/threading.html)、[深圳2026–2028行动计划](https://www.sz.gov.cn/cn/xxgk/zfxxgj/zcfg/content/post_12967660.html)。更完整的事实、日期与推断边界见 [AI趋势证据](ai-trend-evidence.md)。

每个学期末，用少量接受2028届/相应经验的真实职位重新检查方向专项；仅当多个适配岗位反复提出新要求，且已有基础能支撑时，再调整计划。工具发布或网络讨论本身不自动触发换主线。
